# 目标目录重命名

MoviePilot V3 插件。按实际目标存储和整理目标根路径选择电影、电视剧模板。

默认规则严格对应：

| 存储 | 目标目录（包含子目录） | 模板 |
| --- | --- | --- |
| 115网盘Plus | `/影视资源/分享池/已整理/` | 分享格式，含 TMDB ID、技术规格和 `-RMGroup`；剧集不建 Season 目录 |
| 115网盘Plus | `/影视资源/已整理/电视剧/` | 电视剧建 `Season {{season}}` 目录；电影使用简洁格式 |

`/影视资源/已整理/电影/` **未包含在规则内**。需要为该目录启用简洁格式时，请另外增加规则。

## 配置

v1.1.0 起使用表单配置，无需编辑 JSON：

- 每条规则可展开，分别填写名称、选择目标存储及目标目录。
- 目标目录可从已配置媒体库目录中选择，也可手动填写绝对路径。
- 在“电视剧模板”和“电影模板”标签间切换，分别编辑原生 Jinja2 模板。
- 支持添加、复制和删除规则；删除需确认，保存前校验路径、重复目标和模板语法。
- 既有规则自动显示为表单，保存时保持原有配置格式、模板原文和其他设置。
- v1.1.1 起底部操作区沿用宿主透明效果，“添加规则”“取消”“保存”同排显示，规则列表四角保持一致。

内部持久化的 `rules_json` 仍为数组，每条规则包含：

- `name`：备注名称。
- `storage`：MoviePilot 的实际目标存储标识，严格匹配。
- `path`：绝对目录，按目录边界匹配自身及子目录，较长路径优先。
- `movie` / `tv`：原生 Jinja2 模板，空值表示不覆盖该类型。

目录原有的“智能重命名”开关仍有效。插件只选择模板，不改变下载目录、
目录匹配优先级、分类子目录、整理方式、覆盖策略或全局命名配置。
保留 MoviePilot 的命名变量补充、智能重命名事件及字幕后处理流程。

## 实现及兼容

目前针对 MoviePilot v3.2.6 的同步整理计划接口。
通过进程内局部钩子，在原生整理计划读取模板之前建立线程/任务隔离的目标上下文，
并让媒体库文件反查使用对应模板。模板渲染与媒体根路径推导使用同一模板，
避免 Season 层级被误当作媒体根目录。

不修改宿主 Python 文件，不修改 115 插件，不连接网盘执行测试写入。
钩子共享状态保留在宿主模块上，热重载不会反复叠加；已有第三方计划包装仍被调用。
停用插件后新请求直接沿用原生模板；已进入计划的调用保留自己的规则快照。
插件不支持独立分身同时配置规则。

已有文件和已冻结的整理任务不会追溯重命名。验证新规则后再决定是否重新整理历史文件。

## 测试

在 MoviePilot 容器中运行，无需连接网盘：

```bash
python /config/local_repo/plugins.v3/directoryrename/tests/test_routing.py
python /config/local_repo/plugins.v3/directoryrename/tests/test_native_planning.py
```

配置校验测试：`python -m pytest plugins.v3/directoryrename/tests/test_config_ui.py`。
前端数据往返与校验测试：在插件目录运行 `npm test`。
前端使用宿主的 Vue/Vuetify，执行 `npm run build` 生成 `dist/assets` 联邦组件。
校验接口只解析规则，不保存配置，不访问网盘或修改文件。

停用插件即可回退到原来的全局命名规则。
