# 自动生成ED2K链接

## 生活事件路径查询重试（v1.17.2）

新增生活事件的单个文件路径查询出现协议或网络异常时，只对该文件进行递增退避复查，并继续处理同轮其他候选，避免单个异常触发全局轮询退避。

## 生活事件范围外日志（v1.17.1）

115生活事件中不在所选网盘或监控目录范围内的文件会静默跳过日志，但仍保留限次复查，以便文件之后移动到监控目录时正常处理。

## 分组独立等待（v1.17.0）

聚合转发在扫描阶段按剧名和季数预先分组。每个分组独立维护等待窗口：同组新增文件会重新计时并并入原分组，其他剧集、季数或无法识别季数的文件不会互相拖延。链接仍由单线程串行生成，分组发送失败只重试该分组，不影响其他已完成分组；删源仍需满足原有发送成功和身份校验条件。

## 设置页布局（v1.16.2）

Telegram发送与聚合转发开关同行显示；聚合转发延迟等待秒数改为标题下方的输入框。

## 前端构建修复（v1.16.1）

重新构建并发布前端联邦资源，使插件设置中显示“聚合转发延迟等待秒数”输入框。

## 聚合转发延迟等待（v1.16.0）

聚合转发默认在批次完成后等待600秒再发送。等待期间，如果后续本地监控、网盘补扫或115生活事件发现同剧同季文件，会自动并入尚未发送的批次，统一按文件名排序发送；等待秒数可在插件设置中调整为0至3600秒。关闭聚合转发时不等待，仍按单文件发送。

## Telegram 聚合转发（v1.15.0）

聚合转发开启时，扫描阶段先按文件名识别剧名与季数并登记批次，单线程完成整批ED2K计算后，再将同剧同季链接合并发送；不同季、剧名及电影分开发送。补扫和115生活事件各自形成批次，实时文件事件按短暂静默窗口合并。批次超时或单文件失败会转移到后续重试批次；Telegram逐目标状态仍会落盘，全部目标发送成功后才允许删源。关闭聚合转发时保持逐文件发送。

旧版10分钟链接暂存机制已由批次完整性等待替代。

## Telegram 聚合转发（v1.14.2）

开启“聚合转发”后，首个链接会暂存最多10分钟；期间同剧同季的未发送链接会合并为一条消息，链接之间使用换行分隔。超过等待时间仍无同组文件时单独发送，不会永久滞留。不同季数、不同剧名和电影不会合并；消息过长时按完整链接自动拆分。关闭时保持每个链接单独发送。

## 设置页文案（v1.13.2）

精简设置页说明文字，保留删除源文件、大小阈值、目录范围和Telegram授权等必要提示，减少移动端和桌面端的纵向占用；不改变处理逻辑或安全校验。

## 多目录监控（v1.13.0）

本地监控目录、网盘监控目录均支持多个绝对路径，使用英文逗号分隔，各最多32个。旧的换行配置会自动兼容并在保存后规范为逗号分隔。网盘的多个目录属于所选的同一个115／CloudDrive存储，不能在同一实例混用两个存储。浏览网盘后点击“添加此目录”追加并去重，不再覆盖已填写的其他目录。

本地实时监听、定时／手动补扫，以及115新增生活事件，均匹配全部已配置目录。“包含子目录”关闭时，每个目录只处理直接文件，显式列出的子目录仍单独生效；开启时，被父目录覆盖的重复子目录不重复监听或遍历。本地不存在的目录记录警告，不阻止其他有效目录。新增目录后不会主动全量回放生活事件；需要处理已有文件请执行增量补扫。

全部目录仍共用一个串行计算工作线程、原有网盘读取及删除限速，不按目录增加并发或生活接口轮询。文件身份和已有链接记录沿用原规则，避免重复计算、重复投递。TXT仍集中一份，输出路径留空时默认写到第一个本地目录的`ed2k.txt`；仅网盘时写入插件数据目录。调换第一个本地目录会改变默认TXT位置，建议需要固定位置时显式填写输出路径。

115删源授权绑定当前账号、完整目录集合与子目录开关；增加或移除目录后须重新确认授权，不扩大旧记录的删除权限。单目录授权兼容旧版本，单纯调换同一目录集合的顺序不改变授权范围。删除前仍核对文件ID、实际路径、大小和SHA1；CloudDrive仍只读。低于阈值自动删源仍仅限本地，现有开关不自动改变。

## GB显示及生活事件分页（v1.12.2）

最小文件大小输入框固定显示两位小数，例如0.30GB，避免按字节向上取整后反算GB产生长尾。只改变显示；未改动数值时保存保留原始字节阈值（例如500M显示0.49，不因保存其他设置变成0.49GB），用户修改数值后才重新换算。留空可清除大小限制。

复用115插件生活事件库时，按本次监控启用时间和已读事件ID升序分批读取，每次最多64条，后续轮次继续，不再只取最新64条而跳过批量新增；候选队列接近上限时先处理候选，不前移事件游标。仅查询已有数据库，不额外调用115生活接口，不回放本次启用前历史。独立轮询仍每次只拉最新64条，保留上限警告。

设置页区分“最近检查”与“复用事件库最新事件”，超过15分钟无新事件时提示可能暂无活动或上游监听等待整理、更新延迟，不把线程存活或查询成功当成事件实时同步，也不会擅自切换独立轮询。包含子目录仍控制目录范围，不会让上游未写入的事件自动出现；定时补扫独立生效。新版不自动全盘补扫、不代改115插件监听设置。

## 删源前网络校验重试（v1.12.1）

删源前只读查询发生连接或读取超时时，不再误标为永久的身份/授权失败。记录“尚未发送删除请求”，首次失败后5分钟重查，第二次失败后10分钟重查，总计最多3次；每次重新完成原有账号、目录、文件身份和SHA1核验，不跳过任何删除条件，不重新计算ED2K或重复发送成功的TG目标。真实的授权、路径、大小或SHA1不一致仍阻止删除，并显示具体安全原因；未知异常仍保留源文件。删除请求阶段发生超时或响应不明仍为“删除结果未确认”，不自动重删。旧版本已永久阻止的记录不会自动批量解锁，应核实原日志及文件身份后处理。

## 115完成后删源（v1.12.0）

通用设置新增“完成后删除源文件”总开关（沿用原本地 `delete_source` 值），原本地开关不再重复显示；115另外需要“单独授权115网盘删源”，默认关闭，升级不会把原本地授权扩展为网盘授权。CloudDrive继续只读，不提供自动删除。低于阈值自动删源仍仅限本地。

启用方法：选择115网盘Plus和具体网盘子目录，启用网盘增量生成，至少启用TXT或Telegram一种输出；再开启总开关及单独115授权，并在保存时确认风险。授权绑定存储账号、目录和是否包含子目录，每次保存开启的云端授权都须明确确认；关闭总开关或切换到CloudDrive会取消页面上的115授权。仅授权开启时新计算、记录了SHA1证据的文件可自动删源，历史链接不会因开启授权而被追溯删除。

安全顺序：按文件ID查询SHA1 → 流式读取时校验完整大小、ED2K及SHA1 → 持久化有效链接 → 写入所选TXT、完成全部TG目标投递 → 重新核对账号、目录、文件ID、路径、文件类型、大小、时间和SHA1 → 落盘“删除处理中”状态 → 限速按单个文件ID调用115删除接口 → 保存实际结果。缺少SHA1或证据时仍可生成链接，但保留云端源文件。目录、监控范围外文件、CloudDrive、低于大小阈值的云端文件不会被删除，不清理STRM、旁车文件或空目录。

复用115存储登录客户端、UA参数、删除限速器和缓存失效处理，但不调用适配器中失败后可能切换到其他存储的兜底删除路径，避免跨账号回退。SHA1、路径核验与删除请求均设30秒超时；仅对授权候选增加单文件SHA1及强制刷新路径查询，限速等待后再次核对路径，不扫描全盘、不提高计算并发。远端检查与删除不是原子操作，仍不能完全排除同时被其他程序修改的竞态。该115接口按当前存储实现说明为移入回收站，不承诺任何账号都一定可恢复。

明确返回失败时只重试删除，间隔至少300秒、最多3次；不重新下载哈希或重复发送已完成目标。超时、响应状态未知或删除中异常退出时，状态为“删除结果未确认”，停止自动删除重试；需到115人工核实，不能把文件缺失、请求超时或日志异常推断为删除成功。删除前记录保存失败则不发请求；请求成功但最终记录保存失败，原“处理中”记录仍阻止盲目重复删除。查看页展示实际删除结果与说明；云端手动删除按钮仍不开放。

**TG发送成功只表示消息已发出，不代表接收机器人完成转存。** 如唯一备份依赖接收机器人，不应仅凭“已发送”开启删源；本版本没有机器人转存完成回执协议，需自行确认备份策略。

本次升级前完整备份保存在 `/config/plugins_backup/ed2kfolderwatcher-before-cloud-delete-v1.11.7/`，含 `code/`、`data/`、权限受限的 `config.json` 和SHA256清单 `manifest.json`，Telegram SQLite会话使用数据库备份API生成一致副本。回退先关闭插件并停止相关任务，恢复 `code/`，按实例ID `Ed2kFolderWatcher` 恢复数据库配置，再热重载；仅在确有需要时恢复 `data/`，否则保留当前记录以避免重复投递。不要把备份配置、会话或凭证上传GitHub。

## 子目录公共开关与网盘布局（v1.11.7）

“包含本地子目录”和“包含网盘子目录”合并为通用设置中的“包含子目录”，保存后同时控制本地实时监控、本地补扫、网盘补扫及生活事件的子目录过滤。已有配置升级时不自动修改；若原两项不一致，新页面显示待选择状态，必须明确选择后才能保存，避免静默扩大监控或删源范围。网盘开关排列为“启用网盘增量生成 → 115生活事件监控（近实时） → 网盘定时增量补扫”，仅调整位置，不改变启用状态或补扫计划。

### 网盘完成后删源的可行性（v1.11.7历史方案）

网盘不支持删源是本插件的只读设计，不是115或CloudDrive缺少删除能力。当前已安装的115和CloudDrive存储适配器都提供 `delete(FileItem)`，存储插件也有 `delete_file(FileItem)`；媒体增强使用自己的115客户端按文件ID调用删除接口。后续更适合复用已登录的存储适配器，而不是复制Cookie管理与删除请求逻辑；115适配器已有删除限速和缓存失效处理，其接口说明为移入回收站。CloudDrive的恢复能力取决于实际后端，不能统一承诺可恢复。

安全接入应单独实现：先保存有效链接和处理记录，确认所有已选输出成功（含全部TG目标），再重新查询并核对当前存储账号、文件ID、路径、类型、大小和可用内容指纹；拒绝目录、移出监控范围、文件变化及信息不足的目标。115优先按文件ID删除；CloudDrive按路径删除时还存在检查与删除之间被替换的竞态，需更强身份保证，不能声称仅靠事前检查即可消除。删除成功或失败应独立持久化，不把超时当成功，不因删除重试再次计算或重复发TG；远端状态不明时先核实，不盲目重删。保留链接记录及实际删除状态，不顺带清理目录、STRM或旁车文件。

当前TG投递成功只表示发送请求成功，不表示接收机器人已经完成离线下载或转存；如用户依赖接收机器人备份，删除条件还应等待可验证的完成回执或提供额外人工确认，不能把“已发送”冒充“已备份”。

将来若合并为“完成后删除源文件”，不能让现有已开启的本地删源设置在升级后自动授权删除云端文件；需要新增的云端授权与明确确认，默认不启用。低于阈值自动删源仍仅限本地，与生成成功后删源分开。v1.11.7仅调整子目录与界面；v1.12.0实现115单独授权删源，见本页顶部。

## 名称排序与GB数值输入（v1.11.6）

通用设置的最小文件大小固定以GB显示（沿用1024换算，1GB=1024³字节），仅填写数值，支持小数；留空或0不限制。已有带单位配置保持原有实际字节阈值，自动换算显示，例如500M显示0.48828125GB，不会静默提高到0.5GB。旧版配置接口仍支持原带单位字段，新页面使用独立GB字段，禁止同时提交两个字段。若主动改成0.5GB，实际阈值为512MiB。

本地补扫、网盘同目录补扫按自然名称升序遍历（E1、E2、E10），子目录也按名称遍历；已到执行时间的等待文件按路径及自然名称选择，生活事件同一轮查询到的就绪文件排序后一起入队。不增加哈希并发，不为全局排序全盘预读。不同时间到达或尚未稳定的文件不阻塞已就绪文件，不能保证跨多轮事件的整季绝对顺序。查看页仍按最近生成时间倒序显示。

修复同一网盘文件ID在生活事件中为文本、目录查询中为整数时被错误判定为不存在；仍严格检查原路径，不追踪到监控目录外。生活事件首次及最终复查日志明确区分目录、扩展名、大小阈值、临时文件和未就绪，并显示文件名；任务失败日志补充文件名。下载登录页或错误内容依旧拒绝计算，不将错误页当成有效文件，不绕过存储登录及访问限制。

## 本地低于阈值自动删源（v1.11.5）

本地监控新增“低于阈值文件自动删源”，默认关闭，与“成功后删除本地源文件”完全独立。启用后，符合扩展名过滤、经过稳定等待、大小大于0且严格小于通用最小文件大小的本地文件直接删除，不计算哈希、不生成或转发链接，不依赖TXT或Telegram成功。保存开启时需要确认。删除不可恢复，请先用测试目录验证，仅监控下载完成目录；稳定等待不能保证下载完成。阈值留空或0不删除，等于阈值正常生成，空文件继续保留等待写入。删除前校验文件身份及元数据，拒绝变化文件、符号链接或监控目录外路径。该低阈值开关不处理网盘；115成功后删源需要另行授权。已有历史链接和记录不会因该开关清除。

## 页面隔离与最小文件大小（v1.11.4）

手机全屏查看或设置打开时，临时隐藏后台MoviePilot页面，使后台插件列表不再撑高文档或透出；关闭自动恢复，不修改宿主文件。通用设置新增“生成链接最小文件大小”，例如100M、1.5G；支持B/K/M/G/T（也可KB/MiB等）、小数及大小写，按1024换算。留空或0保持原行为；小于阈值的本地、网盘文件不计算、不创建新链接、不补发Telegram、不自动删除源文件；等于阈值可处理。已生成的历史记录与TXT链接不会自动清除，调低阈值后可通过后续事件或手动补扫处理。网盘按元数据过滤，不为判断大小下载文件。

## 手机端宿主滚动锁兼容（v1.11.3）

MoviePilot除Vuetify的HTML滚动锁外，还会将body固定。手机端插件全屏页面现在同时解除这两层固定定位，避免内容虽已展开但文档仍不能滚动；查看页和设置页初次打开时回到页面顶部，避免继承上一页滚动位置导致设置看似未打开。样式仍仅在当前插件全屏页面存在时生效，关闭后恢复宿主滚动锁，不修改宿主源码或用户配置。

## 手机端整页滚动（v1.11.2）

手机及窄屏（小于960px）查看页和设置页不再使用85dvh固定高度及嵌套列表滚动，两段说明与记录一起滚动；MoviePilot全屏弹窗也解除内部高度裁切和独立滚动，使用文档滚动并预留底部安全区。移动浏览器可据自身策略收起地址栏，是否收起由浏览器决定。样式仅在当前插件页面存在时匹配对应全屏弹窗，关闭后自动失效，不修改宿主文件或滚动锁状态；桌面端仍固定标题并仅在列表内部滚动。

## 新增事件延迟复查（v1.11.1）

新增事件可能先发生在资源池，随后才整理进入监控目录。插件按文件ID保留候选最多15分钟，每个文件最多复查10次，常规复查间隔至少60秒；同一候选的后续改名事件可提前唤醒复查。每轮最多检查8个不同文件，候选上限512项，删除事件取消候选，网络异常保留候选并按5分钟起退避。不触发目录扫描，不回放启用前事件；单独改名的历史文件不创建候选。保存配置或重启会清空内存候选，已过期或重启期间漏报的文件需手动或定时补扫。

## 115生活事件严格增量（v1.11.0，延迟复查以v1.11.1为准）

开启115生活事件监控后，只处理启用后新增事件所对应、且当前位于网盘监控目录内的单个文件。生活事件不会再触发整个目录扫描，因此目录中原本存在但尚无记录的文件不会被计算或转发；这些历史文件只由“立即网盘增量扫描／补发”或已开启的“网盘定时增量补扫”处理。目录事件、删除/改名事件、监控目录外文件、零字节和不符合扩展名过滤的文件均跳过；移动进入监控目录的文件可作为新增事件处理。

## 设置名称与网盘定时开关（v1.10.1）

设置卡片统一为“通用设置”“本地监控”“网盘监控”“ED2K链接自动转发”，网盘字段为“网盘监控目录”“网盘补扫计划”。“网盘定时增量补扫”独立控制计划任务：开启且插件、网盘来源均启用时才注册定时补扫；关闭后计划输入框禁用，但不影响手动补扫、115生活事件触发及这些任务的失败重试。生活事件不能保证覆盖所有变化，建议按需启用定时补扫兜底。新配置默认关闭；升级旧版已启用网盘来源时保留其原定时行为（开关开启），保存后可自行关闭，原Cron表达式保留。

- 生活事件默认“复用115插件监听”：只读已运行的115插件生活事件数据库，不额外请求115生活接口；要求115插件监听线程运行且与当前存储为同一账号。不修改其他插件设置、不启动其他插件监听，也不自动回退到网络请求。监听不可用时显示具体原因，定时补扫继续可用。

- 生活事件是账号级信号，但插件会解析事件文件的当前路径，只处理监控目录内文件。目录事件、删除/改名及移出目录事件不会触发计算；部分第三方上传、复制或回收站恢复可能缺少对应事件，因此不能完全取消定时兜底。正在计算的大文件不会并发或被中断。CloudDrive继续使用其独立定时增量计划。

- 网盘采用独立 Cron（默认每10分钟）查询新增或变化文件，不宣称是实时文件系统监控。首次处理所选目录现有文件；后续以存储、文件ID及元数据指纹判断是否重算。变化文件重新计算并重置投递状态；路径或名称变化也重新校验，防止错误沿用链接。

- 需要实际读取时，前后重新列出父目录核对文件ID、路径、大小和修改时间，不以pickcode变化判定内容变化。拒绝空文件、短读、超长读取、错误页和不完整响应。有可用SHA1时额外比对；不能从SHA1直接换算ED2K。缺少可信修改时间时先观察稳定窗口。仅凭云端元数据不能排除服务端在大小和时间等字段不变时替换内容，建议选择上传完成后的稳定目录。
- 失败不保存或发送不完整链接；v1.10.0起按上述策略尝试本次内存续读和跨任务退避。任务进度在设置页查看。暂停/保存配置会等待当前网络读取返回，最长受已配置的读取超时限制。
- **云端默认保留**：v1.12.0起仅在单独授权后，115新增记录满足全部输出与身份校验时允许自动删源；CloudDrive仍只读。云端手动删源API不开放。查看页标记网盘来源、存储名称与实际删除结果。

MoviePilot 本地目录 ED2K 插件。路径填写容器内路径，例如 `/media/movies`，而非未挂载的宿主机路径。

## 实时监控与增量处理

- 默认启用实时监控：创建、移动、修改文件后，等待指定稳定时间再处理；持续写入会延迟处理。文件夹整体移入也会发现其中的文件。
- 单工作线程串行哈希，重复事件合并；处理中发生变化会重新入队。临时下载文件、符号链接、插件输出和缓存不参与生成。
- 默认不启用定时任务。网络挂载等可能丢失文件事件的环境，可开启「定时增量补扫」作为兜底。
- 保存后勾选「立即扫描一次」可补齐现有文件；平时实时监控仅响应新的事件，不会主动重新哈希整个目录。
- 历史链接累计保留，已删除源文件的记录也保留。相同路径大小和修改时间未变时不重新哈希。修改原内容会更新该路径的链接。

## TXT 输出与删除

- 「生成本地 TXT 文件」默认开启，输出路径留空使用监控目录下 `ed2k.txt`。关闭后不会创建或改写 TXT，也不会删除已有 TXT。
- 增量缓存存放在 MoviePilot 的插件数据目录 `Ed2kFolderWatcher/records.json`，与 TXT 路径无关。首次使用自动迁移原输出路径旁的 `.ed2k.txt.cache.json`。
- TXT 和缓存分别使用临时文件、刷新磁盘、原子替换，防止写入一半留下空白清单。
- 「删除源文件」默认关闭。启用时，缓存和已启用 TXT 必须成功保存，已启用 Telegram 必须发送成功，且删除前大小、时间、设备和 inode 未变，才允许删除。
- TXT、Telegram 都关闭时绝不自动删除源文件。请先用测试目录验证删除行为。TXT 和缓存各自原子写入，并非跨文件事务；写入失败会保留源文件并重试。

## Telegram 配置

### 个人账号模式（发送给第三方接收机器人）

Telegram 仅使用个人账号（Telethon）发送，无需选择发送方式，也不要求接收方开启机器人互发。使用独立的个人账号 Session，不导入其他插件的会话，不监听或自动回复聊天消息。

1. 在 `my.telegram.org` 用你自己的账号申请 API ID/API Hash。
2. 打开插件「配置」或「查看数据」，在 **Telegram 个人账号授权** 区输入 API ID/API Hash，点击「保存 API 设置」。API Hash 保存后不回显，留空保持原值。
3. 输入国际格式手机号（如 `+8613800000000`），点击「发送验证码」，查看 Telegram 官方服务消息并输入验证码；如果开启了两步验证，再输入密码完成登录。验证码和密码只用于本次登录，不保存到普通插件配置、日志或浏览器存储。登录流程最多保留 10 分钟，重载插件后需要重新请求验证码。
4. 显示「Telegram 已登录」后，填写接收机器人 `@用户名`，保存插件设置，再点击「增量补扫／补发链接」。不需要终端命令。

请通过可信网络或 HTTPS 使用授权页面。授权接口仅允许 MoviePilot 管理员调用。页面提供「取消本次登录」「刷新登录状态」「退出登录」；退出会撤销本插件会话，保留 API 设置，不影响手机登录。不会自动读取其他插件的凭证或 Session。

如页面暂不可用，仍保留**备用终端工具**（容器名称不是 `moviepilot` 时自行替换）：


按提示完成登录即可。不要在聊天里提供凭证、验证码或密码。只验证授权、不发送消息：


- 未登录、会话失效或权限不足时保留链接与源文件，不会退回 Bot 身份发送。登录完成后保存插件配置解除冷却，再立即扫描一次。
- 依赖见 `requirements.txt`；当前服务器已具备 Telethon。其他环境应通过插件依赖安装流程安装，插件不会自行联网执行 pip。
- 不保证严格恰好一次：网络超时、发送成功后缓存保存失败或进程退出时，补发可能产生重复消息。第三方接收服务是否成功解析，不等于 Telegram 投递成功。

### 发送方式说明

v1.5.2 起仅提供个人账号发送，页面不再显示发送方式选择器或 Bot Token 输入框。机器人发送实现及表单项保留为注释，不会执行，也不会在个人账号失败时回退。旧配置中的模式会归一为 `user`；历史 Bot Token 不回显、不用于发送，保存配置时暂保留旧值以避免擅自清除凭证。

## 哈希实现与参考

采用 9,728,000 字节分块的 eMule 兼容 ED2K。小文件直接 MD4，大文件合并各块 MD4 后再次 MD4；文件恰为整块倍数时包含尾部空块 MD4。优先使用 PyCryptodome 原生 MD4，无该模块时使用纯 Python 回退。实现规则对照 RHash 的 `librhash/ed2k.c`；NanShare 当前部署的是编译后程序，未取得可核验的 ED2K 源码。

隔离测试覆盖多目标解析、去重、部分成功后补发、历史单目标记录迁移、逐目标落盘，以及最近记录、删源状态、网页授权、管理员权限、增量哈希、TXT 和安全删除。浏览器验证查看页与配置页分离、多行目标输入、空记录与错误提示。测试使用模拟个人账号客户端，真实个人账号授权及投递由账号所有者完成，发布时不声称已经完成真实发送。

### 多个 Telegram 接收目标（v1.7.0）

在“接收目标”中每行填写一个频道、机器人或群组，也支持中英文逗号、分号分隔，最多 50 个。可填 `@用户名`、数字 Chat ID 或公开 `https://t.me/用户名`，重复目标自动合并。个人账号需已认识数字 ID 对应聊天，并具备发送权限；频道通常需要发帖权限。

```text
@receiver_bot
@my_channel
-1001234567890
@forum_group|123
```

`|123` 表示该目标的话题 ID；未单独指定时使用默认话题 ID，目标末尾加 `|` 表示不用默认话题。混合发送频道、机器人和群组时，建议默认话题留空，只在论坛群组行填写话题。

所有发送仍使用已授权的个人账号，串行发送、间隔至少 3 秒，不增加哈希并发。每个目标成功后立即保存记录；重试仅发送失败或新增的目标，调整顺序、同一用户名大小写及公开链接格式不触发重复投递。旧版单目标成功记录按原账号和目标迁移。目标别名与数字 ID 无法离线判定为同一聊天，修改这类身份表示可能再次投递。账号级 FloodWait 暂停全部发送，目标错误仅冷却该目标。启用删源时，所有当前目标均成功后才允许删除；失败则保留源文件和链接记录。远端成功但本地保存前异常退出的极小窗口仍可能重发，不保证跨系统事务的严格一次投递。

前端发布前运行 `npm ci && npm run build && npm run test:build`，验证产物中的 Page、Config、AppPage 全部可导入且样式存在，防止重复入口生成未替换路径。浏览器回归页面 `tests/federation-smoke.html` 需通过本地 HTTP 服务访问，直接加载构建产物并挂载三个入口，使用模拟配置接口，不请求真实 Telegram 验证码。

移动端触摸回归：在插件目录启动 `python3 -m http.server 18765 --bind 127.0.0.1`，运行 `python3 tests/verify_mobile_browser.py`（需 Chrome 和 Python websocket-client，可设置 `CHROME_BIN`、`ED2K_TEST_PORT`）。测试覆盖HTML与body双重滚动锁、五种手机/平板/横屏视口，使用原生触摸按下/移动/抬起验证文档滚动、设置和关闭入口、底部命中及关闭后的宿主锁恢复；测试仅访问模拟接口，不保存真实设置或删除真实文件。

复制回归不只模拟 API：启动 `python3 -m http.server 18771 --bind 127.0.0.1` 后，运行 `python3 tests/verify_clipboard_browser.py`（需 Chrome 和 Python websocket-client，可用 `CHROME_BIN`、`ED2K_TEST_PORT` 指定路径及端口）。测试启动临时无头浏览器，在带焦点限制的原生弹窗中执行真实鼠标点击和剪贴板粘贴，验证非安全 HTTP 兼容复制、安全上下文 Clipboard API，以及全部权限拒绝时的链接选中和错误提示。使用独立浏览器配置及模拟记录，不请求真实插件数据、不删除文件。
