# 自动生成ED2K链接

## 上传前秒传复查与普通上传独立转发（v1.21.6）

- 直传任务排队时先做的秒传检测仅作预估；任务取得115独立上传通道后，会再检测一次。若此时命中秒传则跳过普通上传，完成目标复核后复用本地ED2K结果；复查未命中才实际上传。
- 设置页新增“FUCK孤本”模块，可单独配置普通上传专用Telegram目标。只有未命中秒传并完成普通上传、115大小及SHA1核验后，才向该目标发送ED2K链接；每个目标投递状态独立持久化，失败重试只补发，不重复上传。仍复用已授权Telegram个人账号。
- 查看记录隐藏115网盘完整存储路径，保留文件名、上传状态及核验结果。

## 设置页输入框布局（v1.21.5）

- TXT输出路径输入框保持半行宽度，与常规设置输入框一致。
- 115直传模式将上传方式与直传速度上限并排；本地计算上传目录与115上传目标目录并排，使用相同列宽。MP整理模式不显示直传专属字段。

## 单开关启用网盘删源（v1.21.4）

- 网盘监控仅保留“输出成功后删除网盘源文件”开关；开启即绑定当前115账号、已配置网盘目录和子目录范围，关闭即撤销授权，不需再单独开启授权开关。
- 保存时仍校验115账号及目录范围；每次删除前复核文件ID、路径、大小和SHA1。修改监控范围后保存会绑定新范围，旧范围的记录不会沿用新授权删除。CloudDrive保持只读。
- 直传后的115副本删除仍由“网盘副本删除”独立控制，并自动绑定上传目标目录；本地原文件删源开关互不影响。

## MP回执流程与状态（v1.21.3）

- MP模式由MoviePilot按原有目录监控及整理规则复制上传；插件不调用MP整理或115上传接口，只在收到MP上传成功回执后本地计算、核验115副本，再输出和转发。
- 查看页区分“MP回执后处理”和插件115直传。MP任务转发失败时，状态说明仅补发Telegram，不重新上传；设置页MP模式不显示手动计算／上传／补扫按钮。
- 本地计算上传、本地监控和网盘监控卡片的开关合并为同一行，宽度不足时才换行。

## MP上传成功后计算（v1.21.2）

- “使用现有MP整理上传（复制）”仅在收到本地文件复制到115网盘Plus的成功回执后，才计算本地ED2K和SHA1。没有回执、上传失败或本地文件已被替换时，不入队、不读取文件内容计算。
- 本模式不为上传源目录开启文件事件监控，也不递归扫描该目录。启动、每10分钟及手动补扫仅恢复已保存成功回执对应的文件，已有计算结果继续复用；旧版未上传记录不会触发提前计算。若同时配置普通本地监控，重叠的上传目录也必须先有成功回执，其他目录不受影响。
- 插件不会主动发起MP整理或补查历史上传。请先启用插件，再使用MP复制上传，并保留原文件至计算、内容核验及输出完成。网盘重命名继续使用回执关联，最终链接采用网盘文件名。
- “调用115插件直接上传（不整理）”仍先本地计算，再检查秒传／普通上传，行为不变。

## 独立秒传与上传队列、来源删源开关（v1.21.0）

- 本地ED2K/SHA1计算完成后先快速调用115秒传校验；秒传命中后仍需严格复核目标路径、大小及SHA1。未命中或目标目录尚未就绪的文件进入可恢复的普通上传队列。
- 普通大文件上传在独立单文件通道执行，不占ED2K计算/发现队列；后续文件仍能继续计算并快速检查秒传。队列写入插件数据目录，重启后继续处理；上传结果不明时先只读查询，不盲目重复提交。
- 查看页将链接生成、等待秒传/上传、正在核验、115确认上传及失败状态分开显示，并同时列出普通上传队列进度。
- 移除通用“完成后删除源文件”。本地监控、本地计算上传、网盘监控分别设置自己的本地/网盘删源开关，互不影响。115单独授权移至网盘监控；CloudDrive仍只读。
- 本地计算上传新增默认关闭的“网盘副本删除”。它只适用于115直传，必须启用单独授权；授权绑定115账号及配置目标目录，删除前再次校验文件ID、路径、大小及SHA1。仅在ED2K输出成功后执行；结果不明时停止自动删除重试。原本地源文件删除仍由本模块独立开关控制。
- 旧版统一`delete_source`不再自动继承为多个独立开关，避免升级后意外删除本地或网盘文件；升级后请分别检查各模块删源选项，默认关闭的网盘副本删除需单独开启。

## 兼容115 STRM助手接管上传（v1.20.2）

115 STRM助手开启“上传增强”后会将115网盘Plus的上传方法替换为静态入口。v1.20.1只识别原生绑定方法，因此在调用上传前拒绝适配，却提前写入“已尝试上传”；下一轮只查询目标，未找到便提示“上次上传结果未确认”，掩盖首次的接口适配失败。这是本插件兼容性与状态记录的缺陷，不代表本地ED2K计算失败，也不能凭该提示判定115风控。

本版识别已启用的STRM助手接管入口，隔离适配其实际增强上传实现；保留秒传等待、跳过慢传等原策略，不关闭、不全局替换STRM助手补丁，不改变MP其他上传任务。ED2K的已计算SHA1、真实进度、单路直传、限速、停止检查、范围分块校验与最终内容验证均继续生效。增强流程休眠期间可响应停止并检查已到期聚合。

只有即将发出上传初始化请求时才持久化尝试标记；适配检查失败不再假装“已经上传”。查看记录保留首次失败原因，后续退避不再将最初错误完全覆盖。真实初始化或上传之后未获可核验回执仍按原规则保留本地文件、停止盲目重传，上传核验前不转发、不删源。

**旧版已经停止的失败任务不会自动解锁。** 更新后在“本地计算，上传115”卡片点击一次“立即本地计算／上传／补发”，明确允许这些任务复查重试；先严格查询目标，已上传且核验一致的只复用，文件身份未变化时复用本地哈希。请不要反复点击或清空内部记录。

## 上传进度与低负载直传（v1.20.1）

- 修复本地计算上传时因误选“单独授权115网盘删源”无法保存：网盘监控或通用删源关闭时自动撤销网盘删源授权，不影响本地删源选择。本地上传副本仍受保护，不会因为开启本地删源而删除115副本。
- 直传以本地单次读取已计算的SHA1调用现有115上传逻辑，不再重复完整读取SHA1。秒传抽样校验按256KiB分块读取并验证请求范围，避免一次分配过大缓冲。采用本次调用隔离的适配，不改115插件源码、共享对象或全局函数；未知接口不冒险上传，提示更新115插件。
- 查看页区分计算、初始化、传输与最终校验：仅收到真实上传回调才显示上传字节、百分比与速度；等待秒传、提交和校验时不沿用哈希100%。100%仅代表传输完成，仍需115回执及大小/SHA1验证才能输出、转发或删本地源文件。
- 本插件直传始终单文件、串行分片，不读取整部文件到内存。新增“直传速度上限（MiB/s）”，默认8，0不限速，范围0–128整数；仅影响本插件直传，不改变MP或115其他任务。限速用于降低持续I/O与网络压力，不保证提高网盘服务端速度；慢速连接、115限制及其他NAS任务仍会影响吞吐量。
- 上传不再长期占用网盘元数据请求锁；分片间检查到期聚合，避免已完成剧集一直等上传。保存时保留这些检查已写入的投递状态。115初始化/凭证请求30秒超时，OSS连接/读取等待60秒，停止在回调或分片边界生效；不能强制中断已阻塞的底层调用。失败尽力取消未完成分片，取消失败或结果不明仍保留本地文件，不盲目重复上传。

## 本地计算，上传115（v1.20.0）

设置页在「本地监控」上方增加独立卡片，默认关闭，不改变旧版已保存的监控设置。开启插件及此模块，填写容器内的本地计算上传目录（多个用英文逗号分隔），选择以下任一模式：

- **使用现有MP整理上传（复制）**：本插件不主动发起整理、不改MP整理规则，监听启用后的 `TransferComplete` 完成事件，关联本地源路径与115目标文件。请沿用MP的复制上传，保留本地源文件直到计算和关联完成。MP自身可以先完成上传；无论先收到回执还是先算完，本插件均在两者齐备并核验后输出。移动上传、已在启用前完成的整理、其他工具上传及未发布标准完成事件的接管流程不保证关联；无回执时记录停在「等待MP复制上传完成」，不会主动整盘搜索或从115下载全文来猜测匹配。
- **调用115插件直接上传（不整理）**：无需媒体识别、重命名或MP整理规则，复用已登录115网盘Plus的上传接口。填写单个115绝对目标目录，按本地监控根目录内的相对结构上传，缺失的目录由115插件创建。多个本地根目录归入同一个目标根目录；相对路径冲突且大小或SHA1不同会报错保留本地文件，不主动覆盖。不要同时让MP或其他程序写入同一目标路径，现有115接口不提供原子“仅不存在时上传”的保证。

开启或重载后扫描目录内符合条件的现有文件，之后实时监控新增文件，并每10分钟进行增量恢复补扫；不是只处理启用后的新增文件。此模块的监控独立于原「本地实时监控文件」开关；目录重叠时优先执行计算上传流程，不额外进行一次普通本地转发。子目录、扩展名、最小文件大小、稳定等待、重试次数及电影/剧集计算位沿用通用设置。低于阈值的上传来源只跳过，不受原本地「低于阈值文件自动删源」影响。

本地单次读取同时计算ED2K与SHA1，保留本地文件大小、时间、inode等身份信息。大小与115文件SHA1一致且上传期间本地身份未变化，才生成以网盘文件名显示的最终输出；未核验的链接只保留内部记录，不写TXT、不发送TG、不允许手动删源。查看页显示等待MP、上传校验与错误说明，处理队列显示正在计算、调用上传及校验阶段。v1.20.1起本插件接收直传的真实上传进度，初始化或校验阶段不伪造百分比。

直接上传前先严格查询目标；目标已存在且核验一致就复用。网络中断或未返回成功回执时，后续自动重试只查目标，不盲目再次上传；若确认目标未成功创建，可点击本卡片「立即本地计算／上传／补发」明确允许重试。TG失败只补发，不重复上传；保留逐目标投递记录与既有聚合规则。v1.20.1起直传复用已验证的本地SHA1，增加限速、网络等待超时、停止检查与分片间聚合处理，但仍使用原工作线程，底层网络调用未返回时停止或重载仍可能等待。

「完成后删除源文件」在此流程中仅用于本地原文件：上传核验、已选择的TXT/TG输出均成功且再次核对本地身份和115内容后才删除。没有输出方式时不删源。上传后的115副本被关联记录保护，原网盘监控遇到它会复核并复用，不重复全文计算或自动删掉副本。请保留插件记录以维持跨重启保护；清空记录或换名重新上传产生新的文件ID后不再有原关联保护。MP或其他工具自行删除不受本插件控制，必须在MP端关闭提前删源/移动，不能仅依赖本插件的保护。

## 聚合超时不再被未完成文件阻塞（v1.19.3）

此前聚合窗口到期后仍要求同剧同季全部登记任务完成，排队、读取或失败退避中的集数会一直拖住已生成链接。现在每个剧名／季数组独立等待，到期发送当前已完成的链接；未完成文件仍保留原队列与计算顺序，之后完成再在后续窗口补发，不重复发送已成功目标。等待期间发现同组新文件仍重置计时，重复登记同一任务不再延后截止时间。达到重试上限的文件不会阻塞其他已完成链接。

本地及网盘主线程读取分块、网盘重连接口报告进度时，每秒至多检查一次到期分组，串行完成消息投递和安全删源，不新增哈希线程或放宽并发限制。发送发生在下一次读取／重连进度检查或主循环，不是硬实时定时器；底层网络读取阻塞、Telegram限速或正在发送时仍可能延迟。哈希完成后重新加载最新缓存，避免覆盖读取期间已经保存的发送／删源结果。Telegram失败继续按原重试上限处理，所有当前目标发送成功且身份授权校验通过才允许删源。

## 先来先处理与队列显示（v1.19.2）

修复已就绪任务持续按文件名重排造成后来剧集插队：现在本地与网盘共用入队先后顺序，同批扫描发现的文件仍先按名称自然排序入队，后续发现的其他文件追加到队尾，不再全局按名称插到前面。重复收到仍在队列里的同一文件，不会改变其原排队位置。

尚未满足稳定等待或处于失败退避期的任务暂时跳过，避免阻塞已经就绪的文件；失败重新入队的任务排到队尾。启用两路并发时仍只允许电影与剧集各一路，不能占用当前计算位的文件等待对应计算位释放；目录发现与已计算完电影的结果保存仍保持原有调度优先级。队列与后台共用同一排序规则；此顺序基于本次运行实际入队顺序，不是云端上传时间，也不跨插件重启持久化。

安全顺序：按文件ID查询SHA1 → 流式读取时校验完整大小、ED2K及SHA1 → 持久化有效链接 → 写入所选TXT、完成全部TG目标投递 → 重新核对账号、目录、文件ID、路径、文件类型、大小、时间和SHA1 → 落盘“删除处理中”状态 → 限速按单个文件ID调用115删除接口 → 保存实际结果。缺少SHA1或证据时仍可生成链接，但保留云端源文件。目录、监控范围外文件、CloudDrive、低于大小阈值的云端文件不会被删除，不清理STRM、旁车文件或空目录。

复用115存储登录客户端、UA参数、删除限速器和缓存失效处理，但不调用适配器中失败后可能切换到其他存储的兜底删除路径，避免跨账号回退。SHA1、路径核验与删除请求均设30秒超时；仅对授权候选增加单文件SHA1及强制刷新路径查询，限速等待后再次核对路径，不扫描全盘、不提高计算并发。远端检查与删除不是原子操作，仍不能完全排除同时被其他程序修改的竞态。该115接口按当前存储实现说明为移入回收站，不承诺任何账号都一定可恢复。

明确返回失败时只重试删除，间隔至少300秒、最多3次；不重新下载哈希或重复发送已完成目标。超时、响应状态未知或删除中异常退出时，状态为“删除结果未确认”，停止自动删除重试；需到115人工核实，不能把文件缺失、请求超时或日志异常推断为删除成功。删除前记录保存失败则不发请求；请求成功但最终记录保存失败，原“处理中”记录仍阻止盲目重复删除。查看页展示实际删除结果与说明；云端手动删除按钮仍不开放。

**TG发送成功只表示消息已发出，不代表接收机器人完成转存。** 如唯一备份依赖接收机器人，不应仅凭“已发送”开启删源；本版本没有机器人转存完成回执协议，需自行确认备份策略。

本次升级前完整备份保存在 `/config/plugins_backup/ed2kfolderwatcher-before-cloud-delete-v1.11.7/`，含 `code/`、`data/`、权限受限的 `config.json` 和SHA256清单 `manifest.json`，Telegram SQLite会话使用数据库备份API生成一致副本。回退先关闭插件并停止相关任务，恢复 `code/`，按实例ID `Ed2kFolderWatcher` 恢复数据库配置，再热重载；仅在确有需要时恢复 `data/`，否则保留当前记录以避免重复投递。不要把备份配置、会话或凭证上传GitHub。

### 网盘完成后删源的可行性（v1.11.7历史方案）

网盘不支持删源是本插件的只读设计，不是115或CloudDrive缺少删除能力。当前已安装的115和CloudDrive存储适配器都提供 `delete(FileItem)`，存储插件也有 `delete_file(FileItem)`；媒体增强使用自己的115客户端按文件ID调用删除接口。后续更适合复用已登录的存储适配器，而不是复制Cookie管理与删除请求逻辑；115适配器已有删除限速和缓存失效处理，其接口说明为移入回收站。CloudDrive的恢复能力取决于实际后端，不能统一承诺可恢复。

安全接入应单独实现：先保存有效链接和处理记录，确认所有已选输出成功（含全部TG目标），再重新查询并核对当前存储账号、文件ID、路径、类型、大小和可用内容指纹；拒绝目录、移出监控范围、文件变化及信息不足的目标。115优先按文件ID删除；CloudDrive按路径删除时还存在检查与删除之间被替换的竞态，需更强身份保证，不能声称仅靠事前检查即可消除。删除成功或失败应独立持久化，不把超时当成功，不因删除重试再次计算或重复发TG；远端状态不明时先核实，不盲目重删。保留链接记录及实际删除状态，不顺带清理目录、STRM或旁车文件。

当前TG投递成功只表示发送请求成功，不表示接收机器人已经完成离线下载或转存；如用户依赖接收机器人备份，删除条件还应等待可验证的完成回执或提供额外人工确认，不能把“已发送”冒充“已备份”。

将来若合并为“完成后删除源文件”，不能让现有已开启的本地删源设置在升级后自动授权删除云端文件；需要新增的云端授权与明确确认，默认不启用。低于阈值自动删源仍仅限本地，与生成成功后删源分开。v1.11.7仅调整子目录与界面；v1.12.0实现115单独授权删源，见本页顶部。

## 名称排序与GB数值输入（v1.11.6）

通用设置的最小文件大小固定以GB显示（沿用1024换算，1GB=1024³字节），仅填写数值，支持小数；留空或0不限制。已有带单位配置保持原有实际字节阈值，自动换算显示，例如500M显示0.48828125GB，不会静默提高到0.5GB。旧版配置接口仍支持原带单位字段，新页面使用独立GB字段，禁止同时提交两个字段。若主动改成0.5GB，实际阈值为512MiB。

修复同一网盘文件ID在生活事件中为文本、目录查询中为整数时被错误判定为不存在；仍严格检查原路径，不追踪到监控目录外。生活事件首次及最终复查日志明确区分目录、扩展名、大小阈值、临时文件和未就绪，并显示文件名；任务失败日志补充文件名。下载登录页或错误内容依旧拒绝计算，不将错误页当成有效文件，不绕过存储登录及访问限制。

- 直链与请求凭据仅用于当次读取，不写入记录或前端；跨域跳转不转发Cookie和Authorization。当前使用直连请求，不自动套用全局Telegram代理。所有目录浏览、进度和执行接口仅管理员可用。

MoviePilot 本地目录 ED2K 插件。路径填写容器内路径，例如 `/media/movies`，而非未挂载的宿主机路径。

单击插件卡片打开查看页，显示最近 100 条生成记录：文件名、生成时间、ED2K 链接及实际删源状态。页面每 15 秒自动刷新，不自动扫描、发送或删除文件。链接直接展示，点击有效链接即可复制；优先在当前弹窗内同步完成兼容复制，避免弹窗焦点限制和等待权限后丢失用户手势，失败再尝试 Clipboard API。复制成功在当前链接旁提示；浏览器均拒绝时选中链接并提示按 Ctrl+C／⌘C 或长按复制，不虚报成功。手动删源按钮位于状态标签左侧，与“未删除源文件”标签等宽等高。点击右上角“刷新记录”和“关闭”之间的“设置”按钮即可切换到配置页，也可从卡片三个点菜单选择「设置」。切换后停止记录轮询。接收目标输入框默认与话题 ID 输入框等高，不显示滚动条，保留多目标和换行输入。

### 安全生成与手动删除（v1.8.0）

v1.8.3 压缩卡片内边距、时间和链接间距，并将复制反馈预留区从 40px 缩为 20px，减少底部空白。仅记录列表在右侧内部滚动，标题、说明和顶部操作保持可见；滚动条预留独立位置，不遮挡卡片。

v1.8.2 起复制不再触发页面顶部的成功或失败提示，只更新记录内始终预留的固定高度反馈区域。复制成功、失败或切换复制其他记录，不改变卡片高度、文件名、时间和链接位置；长文件名与链接仍按屏幕宽度自然换行，不强制裁切成统一卡片高度。删除操作和读取失败的提示不受影响。

- 零字节文件仅等待后续写入，不生成、不发送链接，也不删除源文件；哈希读取字节数必须与文件大小相符，读取期间的大小和时间戳必须稳定。空内容的 MD4 为 `31d6cfe0d16ae931b73c59d7e0c089c0`，该值配合 `|0|` 表示当时读到空文件，不是完整视频的有效哈希。
- 历史零字节、大小不符或异常哈希记录保留作诊断，在查看页标为无效，不提供复制或删除按钮，并从插件管理的 TXT 链接输出中排除。仍有完整源文件时，监控事件或增量补扫会重新计算、重置投递记录；源文件已不存在时无法从旧链接恢复正确大小和哈希，需要重新获取完整文件。插件不会自动撤回已经发送到 Telegram 的历史错误消息。
- 有效链接对应的源文件仍存在于当前监控目录且元数据匹配时，显示“手动删除源文件”。只有管理员明确确认才会提交删除请求；服务端仅接受记录 ID，不接受任意路径，重新计算并核对哈希，拒绝变更文件、符号链接及目录外路径，链接和记录保留。大文件校验可能耗时；请求超时时请刷新确认实际结果，不要立即重复操作。手动删除是用户主动操作，不依赖自动删源开关或 TG 投递成功，请先确认链接或备份可用。
- 生成和删除仍串行共用锁，不增加哈希并发；稳定等待仅表示文件近期未变化，不能证明下载或复制任务已经完成，建议监控完成目录并避免将未完成下载直接写入监控目录。

设置页右上角保留「保存插件设置」「关闭」。「立即本地增量扫描／补发」和「立即网盘增量扫描／补发」分别位于本地、网盘监控卡片内，只扫描各自配置的来源；两类任务仍共用一个串行计算线程。「保存账号设置」位于 Telegram 账号区域，单独保存授权凭证。

v1.6.0 起记录生成时间及插件实际删除结果。历史记录未保存这些字段时显示「生成时间未记录／删源状态未记录」，不会根据当前开关或文件缺失推断曾由插件删除。新记录优先按生成时间倒序；历史无时间记录按原缓存插入顺序倒序展示。状态为处理时的记录，之后其他程序移动或删除文件不在本插件追踪范围。

链接中直接保留中文、空格、中英文括号等可显示文件名字符。仅 `|`、`%`、`/`、`\`、`?`、`#` 等链接保留符以及换行、制表符等不可显示字符进行百分号转义，避免破坏链接结构。升级启用后自动更新历史缓存及已启用的 TXT，只改文件名显示，不重新计算哈希，不重发 Telegram，也不删除源文件。部分客户端自动识别链接时可能在空格处截断，请复制整条链接导入，而不是只复制自动高亮部分。

## 实时监控与增量处理

- 默认启用实时监控：创建、移动、修改文件后，等待指定稳定时间再处理；持续写入会延迟处理。文件夹整体移入也会发现其中的文件。
- 单工作线程串行哈希，重复事件合并；处理中发生变化会重新入队。临时下载文件、符号链接、插件输出和缓存不参与生成。
- 默认不启用定时任务。网络挂载等可能丢失文件事件的环境，可开启「定时增量补扫」作为兜底。
- 保存后勾选「立即扫描一次」可补齐现有文件；平时实时监控仅响应新的事件，不会主动重新哈希整个目录。
- 历史链接累计保留，已删除源文件的记录也保留。相同路径大小和修改时间未变时不重新哈希。修改原内容会更新该路径的链接。

## TXT 输出与删除

- 「生成本地 TXT 文件」默认开启，输出路径留空使用监控目录下 `ed2k.txt`。关闭后不会创建或改写 TXT，也不会删除已有 TXT。
- 增量缓存存放在 MoviePilot 的插件数据目录 `Ed2kFolderWatcher/records.json`，与 TXT 路径无关。首次使用自动迁移原输出路径旁的 `.ed2k.txt.cache.json`。
- TXT 和缓存分别使用临时文件、刷新磁盘、原子替换，防止写入一半留下空白清单。
- 「删除源文件」默认关闭。启用时，缓存和已启用 TXT 必须成功保存，已启用 Telegram 必须发送成功，且删除前大小、时间、设备和 inode 未变，才允许删除。
- TXT、Telegram 都关闭时绝不自动删除源文件。请先用测试目录验证删除行为。TXT 和缓存各自原子写入，并非跨文件事务；写入失败会保留源文件并重试。

## Telegram 配置

### 个人账号模式（发送给第三方接收机器人）

Telegram 仅使用个人账号（Telethon）发送，无需选择发送方式，也不要求接收方开启机器人互发。使用独立的个人账号 Session，不导入其他插件的会话，不监听或自动回复聊天消息。

1. 在 `my.telegram.org` 用你自己的账号申请 API ID/API Hash。
2. 打开插件「配置」或「查看数据」，在 **Telegram 个人账号授权** 区输入 API ID/API Hash，点击「保存 API 设置」。API Hash 保存后不回显，留空保持原值。
3. 输入国际格式手机号（如 `+8613800000000`），点击「发送验证码」，查看 Telegram 官方服务消息并输入验证码；如果开启了两步验证，再输入密码完成登录。验证码和密码只用于本次登录，不保存到普通插件配置、日志或浏览器存储。登录流程最多保留 10 分钟，重载插件后需要重新请求验证码。
4. 显示「Telegram 已登录」后，填写接收机器人 `@用户名`，保存插件设置，再点击对应来源卡片中的「立即本地增量扫描／补发」或「立即网盘增量扫描／补发」。不需要终端命令。

请通过可信网络或 HTTPS 使用授权页面。授权接口仅允许 MoviePilot 管理员调用。页面提供「取消本次登录」「刷新登录状态」「退出登录」；退出会撤销本插件会话，保留 API 设置，不影响手机登录。不会自动读取其他插件的凭证或 Session。

如页面暂不可用，仍保留**备用终端工具**（容器名称不是 `moviepilot` 时自行替换）：

   ```bash
   docker exec -it moviepilot python /app/app/plugins/ed2kfolderwatcher/telegram_user_login.py --data-dir /config/plugins/Ed2kFolderWatcher
   ```

按提示完成登录即可。不要在聊天里提供凭证、验证码或密码。只验证授权、不发送消息：

```bash
docker exec -it moviepilot python /app/app/plugins/ed2kfolderwatcher/telegram_user_login.py --data-dir /config/plugins/Ed2kFolderWatcher --status
```

- 个人账号模式仅发送完整 ED2K 链接，不加文件标题或其他说明，方便接收机器人解析。接收方服务如果要求先 `/start` 或注册，请用自己的账号先完成。
- 授权文件仅在插件数据目录 `telegram-user/`：`credentials.json` 保存 API ID/API Hash 和用户 ID，`account.session` 保存 Telegram 登录会话。目录权限 700，文件权限 600，源码内不存凭证，也不会上传 GitHub。备份 MoviePilot 数据时也要保护这些文件。
- Session 具有账号访问权限，不是普通配置。可在 Telegram「设置 → 设备」中撤销本工具的授权；再次使用需重新登录。更改 API ID/API Hash 前先在插件页面退出登录；不要共享同一 Session 给其他程序。
- 登录与发送使用文件锁，防止同时操作 SQLite 会话。发送使用独立事件循环和连接，最多等待 60 秒；沿用 MoviePilot 的 HTTP/SOCKS 代理设置（不支持 HTTPS 代理隧道）。同一插件成功发送间隔至少 3 秒，并遵守 Telegram 返回的限速等待。
- 未登录、会话失效或权限不足时保留链接与源文件，不会退回 Bot 身份发送。登录完成后保存插件配置解除冷却，再立即扫描一次。
- 依赖见 `requirements.txt`；当前服务器已具备 Telethon。其他环境应通过插件依赖安装流程安装，插件不会自行联网执行 pip。
- 不保证严格恰好一次：网络超时、发送成功后缓存保存失败或进程退出时，补发可能产生重复消息。第三方接收服务是否成功解析，不等于 Telegram 投递成功。

v1.5.2 起仅提供个人账号发送，页面不再显示发送方式选择器或 Bot Token 输入框。机器人发送实现及表单项保留为注释，不会执行，也不会在个人账号失败时回退。旧配置中的模式会归一为 `user`；历史 Bot Token 不回显、不用于发送，保存配置时暂保留旧值以避免擅自清除凭证。

## 哈希实现与参考

采用 9,728,000 字节分块的 eMule 兼容 ED2K。小文件直接 MD4，大文件合并各块 MD4 后再次 MD4；文件恰为整块倍数时包含尾部空块 MD4。优先使用 PyCryptodome 原生 MD4，无该模块时使用纯 Python 回退。实现规则对照 RHash 的 `librhash/ed2k.c`；NanShare 当前部署的是编译后程序，未取得可核验的 ED2K 源码。

隔离测试覆盖多目标解析、去重、部分成功后补发、历史单目标记录迁移、逐目标落盘，以及最近记录、删源状态、网页授权、管理员权限、增量哈希、TXT 和安全删除。浏览器验证查看页与配置页分离、多行目标输入、空记录与错误提示。测试使用模拟个人账号客户端，真实个人账号授权及投递由账号所有者完成，发布时不声称已经完成真实发送。

### 多个 Telegram 接收目标（v1.7.0）

在“接收目标”中每行填写一个频道、机器人或群组，也支持中英文逗号、分号分隔，最多 50 个。可填 `@用户名`、数字 Chat ID 或公开 `https://t.me/用户名`，重复目标自动合并。个人账号需已认识数字 ID 对应聊天，并具备发送权限；频道通常需要发帖权限。

```text
@receiver_bot
@my_channel
-1001234567890
@forum_group|123
```

`|123` 表示该目标的话题 ID；未单独指定时使用默认话题 ID，目标末尾加 `|` 表示不用默认话题。混合发送频道、机器人和群组时，建议默认话题留空，只在论坛群组行填写话题。

所有发送仍使用已授权的个人账号，串行发送、间隔至少 3 秒，不增加哈希并发。每个目标成功后立即保存记录；重试仅发送失败或新增的目标，调整顺序、同一用户名大小写及公开链接格式不触发重复投递。旧版单目标成功记录按原账号和目标迁移。目标别名与数字 ID 无法离线判定为同一聊天，修改这类身份表示可能再次投递。账号级 FloodWait 暂停全部发送，目标错误仅冷却该目标。启用删源时，所有当前目标均成功后才允许删除；失败则保留源文件和链接记录。远端成功但本地保存前异常退出的极小窗口仍可能重发，不保证跨系统事务的严格一次投递。

前端发布前运行 `npm ci && npm run build && npm run test:build`，验证产物中的 Page、Config、AppPage 全部可导入且样式存在，防止重复入口生成未替换路径。浏览器回归页面 `tests/federation-smoke.html` 需通过本地 HTTP 服务访问，直接加载构建产物并挂载三个入口，使用模拟配置接口，不请求真实 Telegram 验证码。

移动端触摸回归：在插件目录启动 `python3 -m http.server 18765 --bind 127.0.0.1`，运行 `python3 tests/verify_mobile_browser.py`（需 Chrome 和 Python websocket-client，可设置 `CHROME_BIN`、`ED2K_TEST_PORT`）。测试覆盖HTML与body双重滚动锁、五种手机/平板/横屏视口，使用原生触摸按下/移动/抬起验证文档滚动、设置和关闭入口、底部命中及关闭后的宿主锁恢复；测试仅访问模拟接口，不保存真实设置或删除真实文件。

复制回归不只模拟 API：启动 `python3 -m http.server 18771 --bind 127.0.0.1` 后，运行 `python3 tests/verify_clipboard_browser.py`（需 Chrome 和 Python websocket-client，可用 `CHROME_BIN`、`ED2K_TEST_PORT` 指定路径及端口）。测试启动临时无头浏览器，在带焦点限制的原生弹窗中执行真实鼠标点击和剪贴板粘贴，验证非安全 HTTP 兼容复制、安全上下文 Clipboard API，以及全部权限拒绝时的链接选中和错误提示。使用独立浏览器配置及模拟记录，不请求真实插件数据、不删除文件。
