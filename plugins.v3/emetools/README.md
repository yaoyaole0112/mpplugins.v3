# ME工具（MoviePilot 独立版）

“数据补全”页面位于“媒体清理”下：按名称搜索 Emby 剧集，使用 MoviePilot 的 TMDB 密钥补全剧集、演职人员及分集资料；检查 Emby 媒体大小、时长等信息并在确认本机 Emby 身份且服务空闲时，先备份数据库，再短暂停机写入，最后启动 Emby、触发可用的神医任务并复查。停机写库目前只支持单台 Emby，且 Docker 容器名须为 `emby`，MoviePilot 需挂载 Docker Socket。分集图片修复从 STRM 中提取视频地址，以 `jellyfin/jellyfin:latest` 独立容器截帧，标记缺图或疑似偏绿偏紫分集，支持手动选择、强制覆盖，修复状态缓存保存在插件数据中。剧集资料可选 TMDB 或豆瓣优先，不自动启动定时补全任务。首次截帧需拉取容器镜像；务必在 Emby 空闲且已做好备份的前提下进行媒体信息补全。

搜索剧集卡片右上角的“补全设置”保存在本插件配置中：可选择 TMDB 或豆瓣优先、过滤无头像演员、分集演职员、角色名前缀、演员数上限和锁定最低演员数；AI 翻译标题、演职人员姓名与角色、剧集及分集简介、补全角色名。AI 默认关闭，仅当 MoviePilot 已配置兼容 OpenAI 接口的 LLM 并在弹窗手动开启后才会调用；启用前请留意所用 LLM 的计费和数据处理政策。补全任务启动时会冻结一份设置，运行中不可修改。

更新版本时同时更新 `__init__.py` 的 `plugin_version`、`package.json` 的版本号、`package.v3.json` 的 `version` 和 `history` 中对应的 `v版本号` 更新说明；MoviePilot 插件“历史版本”从市场清单的 `history` 读取说明，不能省略。v2.7.0 起已补录仓库可核实的历史说明。

左侧“缺集检测”独立移植原“剧集缺集检测订阅”插件的 Emby/TMDB 扫描、已有季和 S00/未上映过滤、服务器/媒体库/剧集筛选、按季订阅或标记存在、定时任务、历史结果与 CSV。首次进入会复制原插件的检测设置和历史结果，但**不自动启用 ME工具的新定时任务，也不删除或修改原插件配置/历史**。原插件还在运行时，请先在 MoviePilot 停用原插件，再在 ME工具的缺集检测页开启新定时任务；如旧插件仍启用，ME工具拒绝启用新任务及手动执行自动订阅扫描。新增跳过剧集并保存时与原插件一致，会取消该剧集已有的季度订阅，请核对选择后再保存。依赖 `pypinyin` 用于中文剧集按拼音排序。

左侧“媒体清理”提供媒体库扫描、七项始终参与比较的质量规则（可调整优先级）、重复版本列表、选择删除和定时自动清理。检测扫描的媒体库选项仅在点击“开始扫描”后单独保存，不影响定时清理的媒体库；定时清理保存也不会改动手动扫描选项。升级后手动扫描范围初始为空（扫描全部可用媒体库），定时范围维持已有配置。扫描使用 MoviePilot 的 Emby 虚拟媒体库真实路径（而非用户视图中可能为空的 Path）和 STRM 根目录，**两者须在 MoviePilot 容器内指向相同挂载路径**，否则拒绝扫描；片名优先从文件名判别，另解析同名 MediaInfoKeeper `-mediainfo.json`（包括列表式 Emby MediaSourceInfo、ffprobe 格式）以补全码率、大小、编码、分辨率、特效与帧率。不能由文件名和 JSON 确认的来源质量不会猜测或显示 `unknown`；STRM 通常是云端链接，插件不会下载视频以探测质量。115 文件 ID 或 Cookie 不可用、云端删除失败时保留本地文件；删除后请求刷新 Emby。新定时任务默认关闭；启用前请确认其他同类任务已停用，避免重复清理。

插件卡片和插件内部使用同一张自带的 `icon.jpeg` 图标（来源：用户上传的蓝色星形图标）；远端插件清单从本仓库的原图地址加载图标。日志按功能输出扫描开始、候选与隔离结果、115 目录预览/清理、回收站核验与清空、逐规则文件转存，以及 Telegram 频道启动、订阅同步、消息命中与转发结果。频道轮询每分钟记录一次汇总，订阅消息不记录正文；不记录 Cookie、Bot Token、API Hash、验证码或 session。具体记录可在 MoviePilot 插件日志中按「ME工具」筛选。

插件提供清理数据、清理文件、清空回收站、文件转存四项工具；目录规则与定时任务均在插件内运行和保存。

左侧“订阅监控”不重复展示 MoviePilot 的订阅列表；后台读取 MP「我的订阅」用于频道监控，按名称、TMDB ID、年份、媒体类型和季号筛选消息。关键词监控支持正则匹配和黑名单。命中后使用已登录的 Telegram 用户账号把原消息转发到设置中的 Bot。两种监控默认关闭，可分别保存频道并启停；实时监听并每分钟补查最近 15 分钟（每频道最近 30 条）的消息，以补上短暂断线期间的消息；不会批量转发旧消息。监控页面显示实际监听频道数、订阅条数、最近收到消息时间和脱敏错误。插件 `requirements.txt` 声明了 Telethon 依赖，安装后若提示缺少依赖请重新安装插件依赖并重启 MP。

在设置页填写从 my.telegram.org 获取的 Telegram API ID / API Hash、转发 Bot Token，保存后通过手机号、验证码、可能需要的二步验证密码登录。Telegram session 和密钥仅保存在本插件的 MoviePilot 配置中，不通过插件状态 API 返回；请妥善保护 MoviePilot 配置备份。退出登录将同时停止两种监控。

设置页分为“基础设置”和“Telegram 账号”两张卡片，可分别保存，未保存的另一张卡片内容不会随之提交。

清理无效数据的手动扫描直接使用设置页**已保存**的 STRM 根目录，不再另填扫描目录；保存定时清理配置时，也会使用这一根目录。若升级前的定时任务扫描其他目录，页面会显示旧目录警告；保存定时任务前请核对新的清理范围。左上角插件图标内联在前端脚本中，避免联邦加载时绝对资源路径失效。

“清理数据”的定时任务提供无需确认、MoviePilot 页面确认、Telegram 按钮确认三种方式。升级旧配置时沿用原“清理前在 MoviePilot 页面确认”的状态。选择 Telegram 按钮确认前，须在 MoviePilot 通知渠道中为接收该通知的 Telegram Bot 启用“插件”类型，并配置该 Bot 的管理员 ID 与私聊。定时扫描命中后才发送确认/取消按钮；只有对应 Bot 的管理员从私聊点按钮才会处理，令牌 30 分钟过期，重启或取消后失效，执行前仍会核验文件状态。若通知渠道失效，待办也可在 MoviePilot 插件页面查看；不会因为发送失败而自动清理。

首次使用在插件左侧“设置”页面浏览选择 MoviePilot 容器内的 STRM 根目录（默认 `/strm`）；115 Cookie 从同一 MoviePilot 中的“115网盘STRM助手”（`P115StrmHelper`）插件配置实时读取，无需也不能在本插件中单独填写；回收站有独立安全密钥时另行填写。Cookie 不写入本插件配置，也不经插件状态接口返回。115 请求不单独配置代理，沿用 MoviePilot 容器的网络环境。

四项定时任务初次启用时**全部关闭**。启用前请检查其他同类任务，避免重复执行。手动清理会检查扫描令牌、文件状态或 115 目录列表；回收站清空前需重新查询，确认时再次核对回收站数量。无效资料移入 `/strm/.mp-emetools-trash`（或所选扫描根下的同名目录），各批 `manifest.json` 可用于恢复。115 清理进入 115 回收站；115 回收站清空则不可恢复。

本地无效资料定时任务可选择扫描后自动隔离，或创建 MoviePilot 待办、发送 MoviePilot 消息并在插件页确认。115 清理文件手动执行需要预览、生成确认并再次确认；定时清理和定时清空只有明确启用后才执行。

四项工具的通知使用固定标题和正文，类型是 MoviePilot 的「插件」，渠道限定 Telegram；在 MoviePilot 设置 → 通知渠道中，仅给需要接收工具通知的 TG Bot 勾选「插件」通知类型，取消其他 TG Bot 的这一类型即可。此类型由 MoviePilot 的所有插件共用，并非本插件独享：其他插件的「插件」通知也会发给选中的 Bot。定时转存源目录为空且没有错误时不通知，只有实际移动或失败才发送；定时清理目录、回收站为空时不通知；无效数据仅扫描或无清理项目时不发完成通知。手动清理的确认提示与完成摘要在 MoviePilot 插件页面确认。无效数据通知中的隔离目录使用本插件的真实路径 `.mp-emetools-trash`。这些通知不会自动附加插件详情链接。

MoviePilot Bot 支持 `/cleanup`、`/cleanfiles`、`/cleartrash`、`/cleandupes` 和 `/ememove`（执行已保存的文件转存规则）。前三条只进行扫描或预览，彻底删除、隔离和清理必须在插件页面再次查询、预览和确认。`/cleandupes` 按已保存的定时媒体库范围扫描低质版本，仅向发起命令的 Telegram Bot 管理员私聊发确认按钮；确认 30 分钟内有效，核对当前扫描结果后才清理，完成摘要仅回复原 Bot。定时清理的完成通知使用 MoviePilot「插件」类型。手动扫描媒体库与定时清理范围独立；规则可在检测扫描的清理规则弹窗设置。

命令回复严格使用 MP 命令事件携带的 Telegram 渠道来源（Bot 配置名称）；来源缺失时拒绝发送，避免向所有 TG Bot 广播。Bot 命令触发的文件转存仅回复发起命令的 Bot，不额外发送全局工具通知。订阅监控解析转发 Bot 时，Bot API 的 `getMe` 请求沿用 MP Telegram 通知渠道的 HTTPS 代理配置；Telethon 用户账号连接仍由自身客户端负责。Bot 用户名解析结果在当前监控会话内缓存，Token 更新后重新解析，不记录 Token 内容。

源码在本目录，`invalid_data.py` 是安全扫描与隔离，`p115.py` 是独立 115 客户端，`subscription_monitor.py` 为独立的 Telegram 监听器。前端模块联邦暴露 `Page`、`Config`、`AppPage`，插件注册 MoviePilot 侧栏入口。修改前端后执行 `npm install && npm run build`，生成 `dist/assets`。
