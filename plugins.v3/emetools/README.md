在缺集检测结果中点击 **搜索补全**。复用通用设置中的 Telegram API 凭据、已登录用户会话和转发 Bot Token，由用户账号向该 Bot 发送 `/re0 剧名`；自动匹配同名同年份的已入库剧集并选择 115。无法唯一匹配时需人工选剧。此功能仅手动发起，不自动开启定时补全。

资源按明确分集覆盖、覆盖目标集数和积分排序；`S05E01-E28` 可明确匹配，`S05+S00` 或 `1-4季已整理` 仅视为可能覆盖。描述不可作为网盘实际文件清单。确认转存前会提示积分与整包风险；默认单次积分上限 4，可设为 0–100，未知积分、超限、明确不覆盖或已提交资源禁止点击。每次资源点击都需要人工确认。不会自动跟进支付、验证码、额外确认按钮，也不另外转发回复里的链接。

同一个 Bot 串行交互，确认窗口 10 分钟；期间暂缓频道转发并由轮询补漏。请勿同时手动操作此 Bot，检测到其他用户账号消息或菜单变化即停止。提交边界先持久化，超时及重启后禁止自动重试；同一缺失季的未核实任务阻止重复搜索，同一已提交资源保留指纹禁止重复点击。任务记录最多 50 条，未核实任务不自动清理。

点击后由目标 Bot 自己识别链接与转存，依赖已配置的 115 目录监控和 MP 整理链路。提交或 Bot 成功反馈不代表完成：后台每 90 秒只读复查目标 Emby 分集，最多 3 次；也可点击“复查入库”。服务不可用、剧集无法唯一定位、分页不完整时不判定成功。复查不新增或取消订阅；目标集号确实出现在 Emby 中才标记已补全并更新对应缺集记录。转存失败、积分不足、验证码或额外付款提示需在 Telegram 人工处理。人工核实关闭不等于补全成功，且不会解除同资源重复提交保护。

接口：`GET /missing/fill/status` 返回任务与积分上限；`POST /missing/fill/action` 支持 `save`、`start`、`choose_series`、`confirm`、`cancel`、`verify`、`close`，均要求宿主插件管理授权。任务和积分上限保存于插件数据，不记录会话、Token、资源链接或回调载荷。
