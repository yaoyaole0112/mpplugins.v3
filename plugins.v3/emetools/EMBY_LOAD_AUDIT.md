# Emby 负载审计（2026-10-13，2.9.91）

## 结论与证据边界

插件确有可能放大 Emby 负载的路径，不能把所有“转圈”简单归因于网络。
实际插件日志记录同一剧集重复接收入库事件，自动补全重新遍历整剧；2026-10-13
22:30:32.505 写入整剧，22:30:34.702 完成40集写入，约2.2秒内更新整剧及40集。
22:40:57 入库轮询和22:44:09补全任务出现 ReadTimeout。这证明重复写入及接口超时存在，
但没有请求追踪或当时数据库锁/CPU采样，不能证明该批写入是卡住的唯一原因。

Emby 本身还记录 MovieDbEpisodeImageProvider 抓图失败和 SingleImageExtractor 截图错误。
审计时容器运行、当前状态 OOMKilled=false；这不是此前一直健康或没有历史内存压力的证明。
本次检查未对真实媒体进行编辑、批量刷新、停止容器或写数据库。

## 全部模块检查

| 模块 | Emby 操作 | 风险与边界 |
| --- | --- | --- |
| `__init__.py` | 调度、入库事件、页面 API；清理完成后发起刷新 | 配置重载替换工作实例，过去实例锁不能阻止旧任务与新任务并行 |
| `data_enrichment.py` 元数据 | 读取资料；POST整剧/电影/分集 | 自动入库也补全整剧，分集演职同步会遍历历史集；原实现无变更判断和写入节流 |
| `data_enrichment.py` 入库 | Webhook、整理事件和5分钟最近100条入库轮询 | 整理事件原来每次开线程并查询服务器；多个来源能重复安排同一剧 |
| `data_enrichment.py` 媒体信息 | 每页500条全库检查；探测；Extract/Persist计划任务 | 大库检查读取多页；神医任务本身可能操作全库，执行时间和内部并发不由插件控制 |
| `data_enrichment.py` 写数据库 | 检查空闲、停止Emby、备份SQLite写库、重新启动 | **明确会造成短时不可访问**；日志12:29与13:12确有写库记录。重启与恢复初始化可能比实际写库慢 |
| `data_enrichment.py` 分集图片 | 读分集和图片；独立FFmpeg容器；单集Refresh；可触发MediaInfoKeeper缩略图任务 | CPU/GPU、网络、磁盘争用；原Refresh未限制元数据刷新；外部缩略图任务可能扫全库 |

| `p115.py` | 115清理/转存/回收站 | 没有直接Emby API；间接引起MoviePilot整理与入库 |
| `tvmao_client.py`、`tool_notifications.py` | 外部信息及通知 | 无直接Emby读写 |
| 前端及构建资源 | 页面轮询插件状态、用户提交操作 | 状态读取不是逐次全库扫描；重复人工查询仍需负载保护；不改变Emby数据库 |

## 2.9.91 已实施保护

- 电影、剧集、分集写入前比较实际字段；演职比较姓名/类型/角色，不因服务器生成ID、头像标签重复提交。原始完整对象仍用于确需写入的Emby更新，避免丢掉无关字段。
- 每次成功元数据写入后等待至少0.5秒；分集每页300条，替换单次5000条请求。
- 插件补全HTTP和缺集HTTP共享最多2个在途请求。读取起始间隔至少0.15秒，写类请求预约后续间隔至少0.5秒；不限制TMDB/豆瓣外部请求，也不能限制MoviePilot和其他Emby插件流量。
- 补全与缺集扫描分别使用跨实例锁，重载不再绕过原实例运行锁。旧补全实例在下一次请求、写入或批次检查时取消；已提交到服务器的操作无法撤回，当前截帧或数据库安全重启会完成清理后退出。
- 整理事件按媒体类型/TMDB 60秒去重，最多2个解析线程。超额事件由最近入库轮询兜底；轮询每次只看最近100项，极大量入库仍需人工批量补全。
- 清理后全库刷新等待30秒，在等待及刷新调用期间同服务器请求合并；不声称能阻止Emby内部已排队任务或检测其扫描状态。
- 独立截帧容器CPU限制1核、内存1.5GiB；刷新限定单集、关闭元数据刷新，保留图片刷新。GPU/磁盘带宽不受CPU限额保证。
- 明确输出媒体信息补全“即将停止并重启Emby”；保留服务器身份检查、播放/计划任务空闲检查和备份，不改为在线直接写SQLite。

## 仍需注意

1. 正常补全和缺集检测不需要停止Emby；**媒体信息的数据库写入会停止Emby**，请在无人播放的维护时段运行。
2. 批量补全、全库检查、神医Extract/Persist、MediaInfoKeeper以及清理刷新仍有真实工作量，限速不是零负载保证。
3. 自动入库仍遍历已入库分集以保持整剧补全语义，只是相同资料不再写入；尚未改成只补最新一集。
4. 清理仍刷新所有配置服务器，未改为按库刷新；无变更提交判断也不能消除资料源实际变化和AI输出变化产生的写入。
5. 若再次卡住，应记录准确时间，对照Emby日志的数据库锁、抓图/转码、计划任务，以及CPU/内存/磁盘和MoviePilot其他插件，不能仅凭本插件超时认定根因。

回归测试仅使用模拟HTTP、临时文件与临时数据库；不以真实服务器停机/写库作为验证手段。
