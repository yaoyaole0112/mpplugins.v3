# 资源刷流

版本：1.0.2。由站点刷流 6.4.4 完整独立复制，插件 ID 为 `ResourceFlow`，
目录为 `resourceflow`。原 `BrushFlow` 的代码、配置和任务均不修改，不自动导入或接管。
默认下载标签为 `资源刷流-站点名`，不要与站点刷流共用下载标签或同一下载任务。

## Telegram 共享审批

双方实例均完成本地选种、近期播出逐文件筛选和本地去重后，使用已授权的 Telegram
个人账号，向同一个独立 Bot 申请共享下载资格。不读取频道，不通过频道发布推断下载。
只有协调端确认批准并持久化占位，才会暂停添加种子、选择获准文件；
协调端确认入队后才启动下载。电影按媒体类型与 TMDB ID 匹配，剧集另加季集号。
只比较勾选的全部规格；未选字段忽略。共享模式强制核验身份与已勾规格，未知时不抢占。

协调端是本插件内置的 Bot 长轮询线程和 SQLite 数据库，不监听公网端口，
不需要公网 IP、域名或端口映射。只在一台 NAS 开启协调端；其他实例只启用参与审批。
双方及协调端都需要能访问 Telegram。不要将协调 Bot Token 配置给其他 Bot 接收器，
也不要在多台 NAS 上同时运行同一个 Bot Token 的协调端。

## 配置顺序

1. 在 BotFather 创建独立的协调 Bot，记录 Bot 用户名与 Token。
2. 双方启用“自动生成ED2K链接”插件并分别完成个人账号授权，使用各自 Session，
   不复制朋友的 Session 或个人凭证。资源刷流复用该插件 Session 的同一文件锁。
3. 双方个人账号先打开协调 Bot 私聊，发送 `/start`。准备双方 Telegram 数字用户 ID。
4. 在协调机资源刷流右上角飞机按钮打开“共享审批与同规格去重”，选择匹配字段、
   容差及本地规则，保存。协调机开启“在本机运行协调端”，填写独立 Bot Token、
   Bot 用户名、同一个共享组、允许的双方个人账号 ID，保存共享连接。
5. 双方分别填写同一个 Bot 用户名与共享组，设置不同本机名称，开启“参与跨实例共享审批”。
   朋友不填写 Bot Token、不运行协调端。
6. 点击“测试审批连接”，核对返回的个人账号 ID 与协调端规则版本；
   需要时点击“采用协调端匹配字段”，再保存规则。规则不一致时严格暂缓下载。
7. 新建各自资源刷流任务，选择独立下载标签，开启任务“规格去重”，最后启用刷流。
   协调端可以独立运行而不创建本机下载任务。

本机实例 ID 自动生成并持久化。不要把包含该 ID 的完整配置同时克隆给两个客户端。
共享连接设置与本地规则分别保存；Token 已保存时留空不会清除，状态接口不回传 Token。
Bot Token、用户 Session、站点下载链接、Cookie、Passkey 均不会写入共享协议消息。

## 生命周期与故障

- SQLite `BEGIN IMMEDIATE` 在一个事务内完成查重和占位；只使用一个权威数据库。
- 请求编号与内容摘要持久化；同一请求重放返回原结果，编号复用但内容不同则拒绝。
- 每个请求最多 500 个视频文件，消息自动压缩分片并限制消息大小和解压后大小。
  过大的批次暂缓，不绕过去重。Telegram 分片发送间隔至少 1.1 秒并遵守限流退避。
- 整季包默认逐文件申请，只下载获准文件；整包排除模式发生冲突时不创建部分占位。
  多集共用一个物理文件且任一集冲突时，保守排除该文件，不能拆分文件内部单集。
- 共享批准与入队回报都确认后才启动；回报超时保持暂停，占位不释放，
  每分钟最多轮转核验十个未完成申请，或在页面手动提交核验。
- 下载完成逐文件回报为长期证据，不因删种、任务移除或 72 小时自动清空。
  下载中占位无自动过期，心跳失联不能证明原下载停止。
- 本地检查/删种前先持久化已完成文件的证据；完成回报丢失时重放原状态请求，
  不会因为随后已删种而误释放已完成资源。
- 添加结果不确定时保留占位；尝试过添加的种子至少等待五分钟并在两轮查询中确认不存在，
  才释放未完成占位。查询失败、实际选集不一致或无法读取进度时保留待核验。
- 关闭任务去重不申请新资格，但已有共享占位仍核验和回报，不静默释放正在运行的资源。
  协调机或 Telegram 离线时，参与共享审批的新增下载暂缓，不能保证离线时继续下载又绝不重复。
- 未完成申请存在时，不允许更换 Bot、Token、共享组或本机匹配字段/容差。
  不要清理数据库、复制并行数据库或手工删除占位来处理网络超时。

本地选种、类型、黑名单、近期播出、限额、H&R 与删种保护继承自原插件。
未开启全局共享审批时，任务仍可按本地规则运行，但不提供跨实例防重保证。
本插件不接管订阅、手动下载或其他插件新增的任务。人工绕过暂停、修改选集或使用未参与
共享审批的实例，均不在跨实例保证范围内。数据库恢复应停止双方新增下载后协调执行。

## 数据与测试

协调数据库位于本插件数据目录的 `coordinator-*.sqlite3`，请备份整个插件数据目录，
包括数据库、WAL/SHM 文件和客户端申请状态；更稳妥的备份方式是先停止协调线程。
原始 Telegram 消息不写入共享数据库；只保存分片缓冲、必要的资源规格、请求摘要、
批准结果、用户/实例归属与状态。未完成分片一小时后清理，完成证据不自动过期。
个人账号白名单是信任边界，协调程序不能独立验证另一台 NAS 的真实文件完成度。

`tests/` 保留原本地规则回归测试并增加共享协议、并发、消息重放、故障恢复和下载门禁测试。
验证必须使用模拟 Telegram/下载器，不向真实 Bot 发送测试申请或新增真实下载。
原复制版本的说明保留在 `UPSTREAM_README.md`，其中频道功能是上游历史，不适用于本插件。
