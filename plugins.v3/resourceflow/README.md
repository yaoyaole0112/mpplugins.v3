# 资源刷流

版本：1.0.66。由原刷流插件 6.4.4 独立复制，插件 ID 为 `ResourceFlow`，
目录为 `resourceflow`。原 `BrushFlow` 的代码、配置和任务均不修改，不自动导入或接管。
默认下载标签为 `资源刷流-站点名`，不要与其他刷流任务共用下载标签或同一下载任务。

选种沿用本机 MoviePilot 词表的「文件整理屏蔽词」（不区分大小写的正则）。种子标题或包内任一路径命中即排除整颗种子，
人工核验下载也不能绕过；存在屏蔽规则但无法读取包内路径时，暂不下载。
任务下载类型使用 MoviePilot 当前启用的整理分类，支持自定义和多级分类路径。
选定分类后只通过生效分类完全匹配的种子，不用站点标签兜底；留空不限制。
原类型规则在明确选定新分类或取消旧规则后才替换，避免升级扩大下载范围。
全局「种子黑名单」按完整种子标题在所有开启任务级共享下载审批的站点之间查重，
不是禁止这些站点下载。旧任务有手工黑名单时升级默认开启，之后不再使用手工名单。

TMDB 与豆瓣均缺日期时，按包内同剧同季汇总候选。最新已知集的日期在容差内，
即可推断其后缺日期的候选集，不要求集号连续。容差默认 7 天，仅对推断文件适用；
已知日期仍按任务的日期下限判断。AI 官方排播核验默认关闭，开启后沿用 MoviePilot 联网设置，
服务端搜索不可用时改用 MoviePilot 本地搜索。只有可和实际检索到的官方排播证据核对的高置信度结果才自动继续；
有检索来源但证据不足的中置信度条目进入待核验，低置信度或无来源则排除。
推断和 AI 结果记录来源、置信度及日期供复核，推断锚点不是目标集的实际播出日期。

共享申请与占位记录使用统一的右上角半透明状态标签，媒体身份、规格和下载方使用浅背景信息条。
全局设置按基础、运行限额与删种、缺失播出日期、选种与去重、共享下载审批和规范媒体身份绑定分区。
桌面限额四列，身份绑定和协调端配置两列，小屏自动换行。
输入框采用适中高度；连接测试和刷新固定在底部左侧，关闭和保存位于右侧。
账号来源、协调端、最近审批确认在桌面同行显示；去重勾选紧凑排列，缺规格处理紧随其后。
飞机按钮的“共享下载审批”只展示本机下载申请、共享下载记录及下载待核验，关闭按钮位于右上角。
本机下载申请和共享下载记录支持按下载方、媒体类型和状态组合筛选；本机申请的“已过滤”表示本次未下载，命中记录显示的下载进度属于对应下载方。
刷新按钮位于关闭左侧，不再显示顶部去重依据和待核验计数。
本机申请以媒体中文名、季集号、TMDB 及规格信息置顶，原种子标题位于下一行。
整包按同媒体、同季和相同质量字段分组，实际集号连续时压缩为范围，缺集不补齐；
大小为该组物理文件总大小，多集单文件只计一次。任一文件大小缺失时不展示不完整总量，
不同分辨率、特效、编码、来源或帧率分行显示，不将首文件规格套给整包。
同一申请及其相同媒体摘要只展示一次，多文件关联占位只展示首个编号与总数。
同规格过滤只显示下载状态与下载方，不重复展示过滤原因；其他审批错误继续显示。
历史记录按媒体类型与 TMDB ID 复用已保存的中文名，缺失时用可读的媒体原名。两页分别按申请时间、下载时间倒序分页。
去重依据为全部参与设备汇总到同一协调端的有效资源记录，不只是协调机自身记录，也不是所有申请：
被拒绝或尚未确认的申请不代表已经占位。已完成资源在共享下载记录中按“已完成”状态筛选，不再另设共享已完成或旧账本页面；
客户端也可查询共享记录。仅移除重复展示，不删除完成证据或改变共享去重依据。
剧集和电影身份绑定分开维护，可写 `名称或别名 = 规范 TMDB ID`，也可写 `TMDB 旧ID = 规范 TMDB ID`。
映射链会归并到最终 TMDB ID，循环映射会被拒绝。共享审批启用时，协调端是唯一绑定来源并随规则版本下发；
客户端只读同步。新增申请、已有占位和历史完成记录都按规范身份比较，记录中仍保留原 TMDB ID，不会改写旧数据。
任务选种规则的最近播出天数位于对应开关右侧。

## 共享下载审批

记录优先显示已有中文名，缺失时可从文件名补充显示。文件名中的中文只用于展示，
不会改变 TMDB 身份、去重或审批结果，也无需重新导入旧记录。

双方实例均完成本地选种和近期播出逐文件筛选后，仅通过 Tailscale 私网 HTTPS
向同一个协调端申请共享下载资格。不读取频道，不通过频道发布推断下载。
只有协调端确认批准并持久化占位，才会暂停添加种子、选择获准文件；
协调端确认入队后才启动下载。电影按媒体类型与 TMDB ID 匹配，剧集另加季集号。
QB 的文件清单暂不可用时，本机申请显示“等待 QB 文件清单”。后台以约 3 秒间隔最多短重试 3 次，
仍未取得清单则交由常规状态核验继续处理。未确认选集前不启动，也不重复发送占位申请。
只比较勾选的全部规格；未选字段忽略。共享模式强制核验身份与已勾规格，未知时不抢占。
共享审批和近期播出筛选使用 MoviePilot 的识别流程和已保存的识别词。整包逐个识别视频文件，
单文件身份不完整时用种子标题补查媒体身份，季集号仍取自各文件。
共享去重使用识别后的媒体类型、TMDB ID 和标准季集号，不再用原文件名的季集号或中文译名否决识别结果。
影片规格仍按文件名和种子信息提取。两端应使用相同的识别词和数据源配置；已有共享记录不会自动改写。
4K 与 2160p 均按 2160p 比较；HDR、SDR、DV 的变体分别归入各自类别（如 HDR Vivid、HDR10+ 归入 HDR）。
同时标注 DV 与 HDR 的资源归一为 DV，与纯 DV 同规格；纯 HDR 仍单独比较。现有共享记录无需迁移即可按统一规格对比。
共享下载任务超过全局设置中的超时分钟数（默认 30 分钟）仍有获批文件未完成时，先停止并移除下载器任务但保留数据；
确认任务已移除后只释放未完成文件占位，已完成文件记录继续保留。
共享任务不使用频道或本机历史作为跨设备去重依据；客户端优先使用协调端记录的本地镜像，
镜像未命中仍统一由协调端查重并占位。开启协调端的设备直接读取本机权威库做预筛。
入队同规格去重、种子包内同规格逐文件去重、2160p 优先固定开启；整包固定按剩余文件逐文件下载，身份不完整时固定等待核验。这些策略不再提供界面选项，协调端和所有客户端统一采用相同规则。
同集已有获批占位或已入队的 2160p/4K 时，暂缓 1080p 或更低分辨率候选，
避免两台设备同时下载不同清晰度。2160p/4K 完成后按文件过滤低分辨率候选；
失败并确认释放后，下次刷流可重新申请。整包包含暂缓文件时先不入队，
否则同一 Hash 部分下载后无法再申请剩余文件。此规则不取消已经开始的低分辨率下载。
该判断不依赖“全局去重字段”是否勾选分辨率，由共享记录预筛和协调端最终审批共同执行，
请先更新运行协调端的设备。

## Tailscale 私网 HTTPS

1. 保留双方的共享组、本机实例 ID 和原协调库。已配置 HTTPS 的实例升级无需重新绑定。旧 Bot 审批入口不再运行；只在一台设备上启用协调端。
2. 分别为协调机和客户端生成独立密钥和 SHA-256 指纹。在各自可信终端执行以下命令一次，仅将密钥通过安全渠道交给对应设备；协调端的设备列表只填指纹，不填原密钥。

   ```sh
   key=$(python3 -c 'import secrets; print(secrets.token_urlsafe(32))')
   printf '密钥：%s\nSHA-256：' "$key"
   printf '%s' "$key" | sha256sum
   unset key
   ```

3. 本机下载审批关闭时，先保存协调端的“提供私网 HTTPS 审批入口”。“允许的私网设备”每行填写 `本机实例ID 账本所有者数字ID 密钥SHA-256指纹`，中间用空格。已有占位的实例须沿用原所有者 ID。保存后查看“共享账本 ID”。
4. 从 Tailscale Serve 私网 `443` 只代理 `/resourceflow-approval/v1/rpc` 到资源刷流接口，禁止用 Funnel、映射 MoviePilot 端口或放通整个子网。协调端插件只监听 `/config/plugins/ResourceFlow/approval-private/rpc.sock`。Docker 里可用一个小转发容器，共用专用 Tailscale 容器网络命名空间，把该 socket 接到命名空间自己的 `127.0.0.1:18764`。例如（把 `MP_CONFIG` 改成协调机 MoviePilot `/config` 对应的宿主机路径）：

   ```sh
   SOCKET_DIR="$MP_CONFIG/plugins/ResourceFlow/approval-private"
   test -S "$SOCKET_DIR/rpc.sock"
   docker run -d --name resourceflow-approval-relay \
     --network container:tailscale-resourceflow --restart unless-stopped \
     --cap-drop ALL --security-opt no-new-privileges --read-only \
     --mount "type=bind,src=$SOCKET_DIR,dst=/run/resourceflow,readonly" \
     --entrypoint socat docksal/socat:latest \
     'TCP-LISTEN:18764,bind=127.0.0.1,reuseaddr,fork,max-children=16' \
     'UNIX-CONNECT:/run/resourceflow/rpc.sock'
   docker exec tailscale-resourceflow tailscale serve --bg --https=443 \
     --set-path=/resourceflow-approval/v1/rpc \
     'http://127.0.0.1:18764/resourceflow-approval/v1/rpc'
   ```

   只允许对端设备访问专用协调节点 TCP `443`。转发容器不发布端口，不挂载 Docker Socket、配置目录或媒体目录。若重建专用 Tailscale 容器，也要重建转发容器，让它引用新的网络命名空间。客户端容器如无法正常解析 Tailscale 域名，修复容器 DNS，或重建时保留原参数并用 Docker `--add-host` 持久化该域名与 Tailscale IP 的映射。
5. 逐台填写本机密钥，再启用并保存共享下载审批。远端客户端还要填协调端完整 Tailscale 域名与共享账本 ID；本机协调端通过 Unix socket 请求。之后点“测试审批连接”，核对规则版本和原下载记录。

增量同步、占位、入队、完成和释放只走私网，原账本、实例绑定和未完成占位保持不变。
HTTPS 使用正常证书校验，不通过 MoviePilot 代理、不跟随重定向；请求失败时新增下载暂缓，
待恢复后沿用原申请继续核验。协调端可以独立运行而不创建本机下载任务。

本机实例 ID 自动生成并持久化。不要把包含该 ID 的完整配置同时克隆给两个客户端。
全局设置底部“保存设置”依次保存共享连接、去重规则及原全局选项；任一步失败均明确提示
未全部保存，保留弹窗，已保存的部分不自动回滚。设置尚未读取成功时禁止覆盖保存，
定时刷新不会覆盖正在编辑的全局草稿。未启用共享审批时，身份绑定只在本机生效；
启用共享审批后，仅协调端可编辑，客户端通过协调端规则同步身份绑定。
私网密钥已保存时留空不会清除，状态接口不回传密钥。
站点下载链接、Cookie、Passkey 均不会写入共享协议消息。

## 共享下载记录缓存

- 协调端和客户端均更新至 1.0.26 后自动启用，无需额外配置；旧协调端仍使用原有审批，不请求增量接口。
- 客户端首次分批同步、重启续传；之后有刷流候选或查看记录时约每分钟更新，空闲约每 9～10 分钟更新。
  每轮最多同步一页，以协调端记录的递增序号合并新增、完成、释放及删除。切换共享组、协调端或规则版本重新同步。
- 缓存命中同身份、集号重叠且所有已勾规格一致时，本地排除，不发占位消息；整包按原有 `partial` / `exclude` 策略处理。
  活跃占位缓存最多用两分钟，已完成记录最多用十分钟；初次同步未完成、增量落后、缓存过期或同步失败时，回退协调端审批。
  两台设备同时缓存未命中，仍只能有一台获准。审批未确认绝不启动下载；入队、完成和释放状态继续按原流程回报。
- 镜像追平后，客户端的共享下载记录列表用本地数据搜索和翻页。日志中的“共享下载记录本地命中”表示已省去一次候选申请；
  同步使用所选传输，整体审批请求数取决于候选重复率。

## 生命周期与故障

- SQLite `BEGIN IMMEDIATE` 在一个事务内完成查重和占位；只使用一个权威数据库。
- 私网审批入口有并发上限；账本锁等待超限会返回「协调端审批繁忙」，只暂缓当前请求，不触发全局连接退避。
  本机审批响应超时与远端域名、TLS 错误分别记录；慢请求日志包含操作、申请编号与耗时，不记录密钥。
- 本机下载申请保留执行及恢复过程，不是所有申请都会创建占位：被排除的文件关联命中的已有占位，
  获准的文件关联本申请占位。记录页面显示双方关联编号，便于核对，不能用本机申请是否存在代替共享裁决。
- 请求编号与内容摘要持久化；同一请求重放返回原结果，编号复用但内容不同则拒绝。
- 每个请求最多 500 个视频文件，并限制请求大小。过大的批次暂缓，不绕过去重。
  成功收到完整裁决后清理旧退避报错。缓存不能批准下载，所有本地未命中的候选仍由协调端原子查重并占位；
  规则版本变化会拒绝旧规则申请并触发重新同步。
- 整季包默认逐文件申请，只下载获准文件；整包排除模式发生冲突时不创建部分占位。
  多集共用一个物理文件且任一集冲突时，保守排除该文件，不能拆分文件内部单集。
- 共享批准与入队回报都确认后才启动；回报超时保持暂停，占位不释放，
  每分钟最多轮转核验十个未完成申请，或在页面手动提交核验。
- 下载完成逐文件回报为长期证据，不因删种、任务移除或 72 小时自动清空。
  下载中占位无自动过期，心跳失联不能证明原下载停止。
- 所有共享状态读取同一张协调端资源表，比较全部未释放的同身份记录，不只比较页面当前页
  或近三天记录；已释放记录仅保留审计，不阻止后续重新申请。
- 本地检查/删种前先持久化已完成文件的证据；完成回报丢失时重放原状态请求，
  不会因为随后已删种而误释放已完成资源。
- 添加结果不确定时保留占位；尝试过添加的种子至少等待五分钟并在两轮查询中确认不存在，
  才释放未完成占位。查询失败、实际选集不一致或无法读取进度时保留待核验。
- 文件清单暂时不可用时，共享下载保持暂停并由每分钟巡检重试选集；获批集下载超过两小时后，
  停止并移除下载器任务但保留文件数据，确认任务已不存在后只释放未完成集，已完成集保留长期占位。
  停止、移除或状态查询未获确认时继续保留占位；整包仅按本申请获批的文件判断，不把未获批集计入完成度。
- 关闭任务去重不申请新资格，但已有共享占位仍核验和回报，不静默释放正在运行的资源。
  任务开启“共享下载审批”但全局未启用或配置缺失时，暂缓新增下载，不能静默降级为本地下载。
  下载器添加前另行核对任务、下载器、Hash、申请阶段及精确获批文件，始终暂停添加；
  已排除、已释放或已完成的申请不允许重新启动。
  协调机或私网不可达时，参与共享审批的新增下载暂缓。
- 未完成申请存在时，不允许更换共享组或本机匹配字段/容差；更换连接须能核验原占位。
  不要清理数据库、复制并行数据库或手工删除占位来处理网络超时。

## 旧记录兼容与升级

升级保留原本机账本，不直接删除历史。仅把标记为真实下载完成、身份有效、已勾规格完整且有有效时间的
本插件旧证据补入协调端已完成记录；已核验完成的本机申请保留原申请及占位关联。
频道发布记录、无法确认身份、规格不全及失效身份不会提升为共享完成证据，页面提示待核验数量。
未通过的旧完成证据不会按时间自动删除或自动变成待同步任务；只有补齐所勾字段等必要证据，
后续同步校验通过才可导入。历史不完整证据说明仅在下载待核验页和全局设置显示为信息提示，
不在本机申请及共享下载记录页持续告警，不影响其他合格资源审批；真正待同步、关联异常仍显示警告。
未勾字段缺失不影响补录。普通历史多集证据按集导入，已有审批的多集物理文件保持原完整集数关联。

协调端先补入自己的旧完成证据，再开始接收 Bot 审批；客户端在新增申请前先同步自己的待补录证据。
补录有持久化回执并可重放，不会每轮重复创建历史占位；发现原完成占位缺失时只恢复已确认的完成证据，
不为缺失的运行中任务重新申请。关联缺失、归属或状态不一致时明确报警并暂缓新增下载。
定期核验本机申请与协调端关联，周期十分钟；缺失异常会触发重新核验，协调数据库重建会重新同步完成证据。
历史证据只在本机运行时才能同步，所以升级时应暂停双方新增下载，先升级协调端，再让全部客户端完成
连接及历史同步，确认无待同步和关联异常后恢复刷流。离线设备尚未提供的历史不能凭空补齐。

本机账本此后只作为兼容归档和历史补录来源，共享界面不提供移除本地证据来绕过协调端完成记录的入口。
信任边界仍是协调 Bot 的个人账号白名单，协调端不能独立证明另一台 NAS 提供的历史完成度。

下载待核验是本机诊断列表，记录身份、季集号或已勾规格无法确认的候选，也可能包含旧下载完成但
身份尚未确认的文件；不是共享占位、已批准下载清单或独立定时重试队列。
共享候选无法核验时不申请下载资格。可以在 MoviePilot 中保存识别词，等待后续刷流重新识别，
也可以人工核验。重新识别且勾选规格齐全的旧条目会移出待核验，正在人工处理的记录不受影响。

“核验下载”复用本机暂存的 `.torrent` 文件，不重新向站点取种，也不保存或同步原始下载链接。
暂存最长 24 小时；过期或被清理后需等刷流任务重新获取。人工提交不重跑发布时间、分类等
已执行的站点选种规则。近期播出已通过且媒体身份和季集号未变的文件不重查日期；旧记录缺少
通过凭证、日期尚未核验或修正了身份时，如原任务开启近期播出规则，仅核验所选文件的日期。
仍检查现有运行限额、MoviePilot 整理屏蔽词及下载器 Hash。共享去重和占位通过后才交给下载器，
整包仅下载本次核验并获批的文件。

本地选种、类型、黑名单、近期播出、限额、H&R 与删种保护继承自原插件。
任务明确关闭“共享下载审批”时，仍可按本地规则运行，但不提供跨实例防重保证，
日志会标记“共享审批旁路”。全局关闭不会自动把仍要求审批的任务变成本地模式。
本插件不接管订阅、手动下载或其他插件新增的任务。人工绕过暂停、修改选集或使用未参与
共享审批的实例，均不在跨实例保证范围内。数据库恢复应停止双方新增下载后协调执行。

## 数据与测试

协调数据库位于本插件数据目录的 `coordinator-*.sqlite3`，请备份整个插件数据目录，
包括数据库、WAL/SHM 文件和客户端申请状态；更稳妥的备份方式是先停止协调线程。
`shared-record-cache.sqlite3` 是可重新同步的客户端镜像，不是权威记录库。
共享数据库保存必要的资源规格、请求摘要、批准结果、用户/实例归属与状态。完成证据不自动过期。
站点只同步显示名称，不同步站点地址、凭据或种子链接。历史完成记录只从原申请或按
种子 Hash 匹配的本机下载记录补录，由原下载实例上报；不会覆盖已有站点。
允许的私网设备是信任边界，协调程序不能独立验证另一台 NAS 的真实文件完成度。
每个文件的批准/排除日志包含 TMDB、季集、勾选规格、申请编号、任务、下载器、Hash，
冲突时另列已有下载方与占位状态；实际启动后记录“共享审批启动确认”。
频道发布时间不能作为下载开始时间或审批通过证据。排查重复时，应对照双方本机的申请、
启动日志与实际下载来源，不把已拒绝的请求当作已下载。

`tests/` 保留原本地规则回归测试并增加共享协议、并发、消息重放、故障恢复和下载门禁测试。
`npm run test:display` 覆盖整包集号压缩、物理文件总大小、不同规格分组及排除原因合并；
浏览器验证覆盖顶部按钮、记录信息顺序、整包摘要、搜索筛选与浅深玻璃主题。
测试使用模拟审批与下载器，不新增真实下载。
原复制版本的说明保留在 `UPSTREAM_README.md`，其中频道功能是上游历史，不适用于本插件。
