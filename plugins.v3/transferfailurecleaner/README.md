# 失败整理记录清理

适用于 MoviePilot V3。根据「媒体整理」页面实际失败提示生成多选列表，按勾选类型精确匹配并清理失败记录。通过 GitHub 插件仓 `https://github.com/yaoyaole0112/mpplugins.v3` 安装，不依赖本地插件仓。

## 使用

1. 在 MoviePilot 插件市场添加上述 GitHub 仓库，刷新后安装「失败整理记录清理」。插件默认关闭，默认不勾选任何错误类型，默认仅删除记录。
2. 打开配置，勾选错误提示类型。选项后显示当前数量；已选但暂时没有记录的类型仍保留，以便以后继续定时清理。
3. 选择删除方式，设置 Cron（默认 `0 3 * * *`，按 MoviePilot 时区每天 03:00），按需设置保留小时数，保存配置。
4. 在「查看数据」点击「预览匹配记录（不删除）」核对范围；实际清理用「立即清理已选类型」。启用定时清理开关后按 Cron 自动执行。
5. 新的错误提示出现后重新打开配置页并勾选，不会自动纳入清理。

## 安全边界

- 只匹配失败整理记录，不影响成功记录。文件是否删除由保存的删除方式决定；手动清理和定时清理使用同一方式。
- 四种方式与 MP 删除弹窗的按钮文案和后端参数一致：
  - **仅删除转移记录**：源文件、媒体库文件和下载任务不受影响。
  - **删除转移记录和源文件**：删除源文件，不删除媒体库文件。
  - **删除转移记录和媒体库文件**：删除目标文件，不删除源文件或下载任务。
  - **删除转移记录、源文件和媒体库文件**：删除两侧文件。
- 选择源文件删除时，复用 MP 原生删除命令：源文件删除或确认已不存在后，发布宿主的 `DownloadFileDeleted` 事件，联动删除同一下载哈希对应的下载任务（`delete_file=False`），不额外删除下载数据文件。事件具体执行和其他插件联动由宿主处理；没有哈希或未找到任务时不会删除下载任务。
- 下载任务不作为独立第五项，避免偏离 MP 原生四项语义。源文件可能只属于一个多文件种子的一部分，但宿主仍按整个下载哈希移除任务，选择前请确认。
- 涉及文件的删除不可恢复，请先使用预览。预览只核对失败类型和保留时间，不调用文件删除或下载器接口，也不保证宿主最终允许删除；某一侧文件处理失败时宿主保留记录，但另一侧可能已经删除。
- 按媒体整理接口相同的公开错误提示精确匹配，不使用模糊关键词或正则。不同原始异常被宿主转换为同一公开提示时，属于同一个类型。
- 无错误提示单独显示为「（无错误提示）」，只有明确勾选才清理。
- 大于零的保留小时数按记录时间过滤，时间缺失或无效时保留。
- 删除前重新核验状态、错误提示及保留时间。旧记录加行锁；持久任务记录由宿主删除命令通过状态机原子核验并放弃失败任务，拒绝时保留并写日志，不越过宿主的租约和结算版本校验。
- 清理后无法再从该记录手动重试，宿主会同步清除对应失败重试缓存；文件之后仍可能因监控或扫描重新产生整理记录。
- 手动操作仅允许管理员，使用已经保存的配置；同一实例不允许清理任务重叠执行。
- 执行摘要和按类型匹配数量保存在插件数据页面；完成后重新打开页面查看更新。

## 验证

在 GitHub 仓库根目录执行：

```bash
python3 -m unittest discover -s plugins.v3/transferfailurecleaner/tests -v
```

插件依赖当前 V3 的历史删除命令与运行时装配接口，不承诺 V2 兼容。
